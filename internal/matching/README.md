# 元数据输入证据

本目录同时保留检索评分与严格元数据证据，两者不可替代。**展示分数不等于身份概率**。

## 入口与隔离

- `Weights.ScoreCandidate`、`CompareTitle`、`CompareCredit`：既有检索展示与歌词比较入口，默认权重及旧语义不变。
- `NewInputProfile`、`ParseMetadataText`、`ParseMetadataCredit`：本次元数据输入的证据模型，保留原文、规则版本、未知注释和完整限定。
- `CheckMetadataEvidence`：只检查一个候选是否满足本次输入，不检查收藏、不选择发行、不授权写入。
- `CheckMetadataPool`：保留 eligible / excluded / unresolved 三类；有未排除的未知竞争者时不得进行自动选版。
- `MetadataFacts` 必须来自同一套有出处的事实，不能把互相矛盾的用户当前值与上游快照拼为假候选。完整性及位置验证由资料提供者声明，不由搜索排名推断。

Runner 传递持久化 profile，`library.SelectCandidate` 先按完整输入筛选，再对相容目标判组和选版。4.4–4.6 已接入输入优先入口、已收藏兼容 track 偏好及统一自动提交分支。歌词不读取这些新元数据规则。

## 来源身份与接受准备

- `CandidateResolver` 由 matching 声明，`InspectCandidate` 不出网；`LoadDecisionFacts` 按给定候选返回同序结果，明确区分 exact / ambiguous / not_found / insufficient / invalid / unsupported。上游错误保留为错误，不伪装为空结果。
- `CandidateSources` 在 App 集中装配，library 通过注入消费。非 App 的 registry 调用按能力接口发现来源，不按来源 ID 分支。
- MusicBrainz 的 `recording@release` 仅用于召回。解析只查询给定发行，检查完整清单、真实 track、碟序和位置；同发行多位置不按首项或收藏状态选择。同次发行共用解析结果，并复用已有响应缓存、配额和重试。
- iTunes 在来源内检查小写 storefront 与曲目/发行一致性；QQ 在来源内检查 MID。已有精确候选不额外出网，未实现的决策清单补取明确 unsupported。
- `library.PrepareCandidate` 先解析再创建 seed；`CandidateSeed` 和直接 `PrepareAdmission` 均重新检查精确身份及一致的发行关系，不允许合成 seed 绕过。完整身份不要求展示字段齐全，缺失名称/署名仍保持未提供，不能借输入填充。
- `App.PrepareAdmission` 返回正常计划，或者仅带 `resolution` 的候选展开结果。后者没有可提交的计划 ID/hash，前端不调用 commit，而是回到列表选择真实位置；展开说明显示碟号与轨号。直接接受/加入兼容入口不能提交展开结果。
- 自动解析得到的真实候选再执行输入证据核验；仍有未解析目标时保留复核，Runner 保存展开候选而不是错误的合成收藏。问题修订和多行事务仍属于后续任务，不能由身份解析测试推定已完成。

## 精确所有权

`ResolveLocal` 先经注入的来源能力验证身份，再通过 `LocalLookup.FindExactBinding` 一次读取当前 track 和发行绑定及修订。仅来源、真实 track、发行关系均一致时返回 `owned` 和本地 ID；ISRC、Recording、相似文本及旧绑定快照不参与拥有判定。结果区分 `unowned / owned / identity_conflict / lookup_error`，错误和冲突不携带可跳过的本地目标。

未解析候选保留 `identity.state=unresolved`，不查询本地精确拥有、不妨碍后续目标解析；不支持身份检查及数据库失败明确返回错误。当前候选 DTO 已传递结构化结果，单行 `PrepareSkipExisting` / `CommitAdmission` 已支持精确跳过和输入修订重验，见 [store 事务说明](../store/README.md#单行接受与精确跳过)；共享候选表格已按 `accept / skip / add / owned / unavailable` 枚举及结构化所有权分流，中文文案只用于显示。同 ISRC 的不同 track 独立呈现，错误与冲突禁止动作；搜索加入后由服务端重新读取所有权，不用返回 ID 在浏览器伪造绑定修订。旧 `LocalDuplicateLookup` / `CheckLocalDuplicate` 前置短路已删除，未绑定文本只参与相关事实召回，不阻止上游候选入库，也不能给原曲目自动写绑定。

## 候选本地刷新与封面身份

当前实现增加 `RefreshReviewCandidates`，与搜索刷新共用本地身份查询；只刷新给定候选，不回到旧候选池或执行上游搜索。复核页订阅收藏变化，保留输入草稿与当前候选，并按候选请求代次拒绝迟到刷新。两个页面提供“刷新本地状态”；整次刷新失败时保留正文，以 Wails `CandidateRow` 构造器生成不可操作的错误态，不将错误伪装为未收藏。

`CandidateCoverTarget` 按候选自己的来源发行读取本地 ID 与封面修订，快照重载和预取不信任旧本地 ID；封面归属查询失败通过 `coverError` 单独表达。封面 URL 同时携带已知来源发行身份，服务端拒绝本地 ID 与来源不一致的请求。纯本地发行调用仍可只使用本地 ID。

应用测试覆盖删除、曲目/发行换绑、旧快照与相关封面 ID、数据库错误及恢复，并断言本地刷新不请求上游。浏览测试覆盖新查询、切换条目、卸载重进、迟到成功/错误，以及队列刷新与收藏事件的两种返回顺序；提交断言核对当前 track、输入 ID 与修订，不仅检查按钮数量。测试桩按 Wails 的 JSON 边界复制候选，并持久化改搜候选与输入修订；不能对 Vue 响应式 Proxy 使用 `structuredClone`，也不能让静态旧队列冒充改搜后的服务端状态。具体执行结果与验证边界见本变更 `handoff.md`。

## 同一目标的事实合一

`library.CandidateFacts` 读取本地文本召回，并通过 matching 声明的 `LocalFactLookup` 补读远程精确 track 的本地事实；即使当前值和快照名称完全不同，也不能漏掉这个精确目标的来源冲突。`BuildCandidatePool` 只按来源检查的精确 track 聚合，未绑定记录留在 Related，未解析候选不按文本或 Recording 合一。

每个目标保留 remote、current、snapshot、tracklist 独立事实视图与出处/修订。完整发行清单中该 track 的位置是独立视图，不填补其他快照缺失字段；部分清单不提供本地位置完整性。用户改名保留在当前视图，有效快照仍可匹配原名/可靠异写；当前显示值不能覆盖来源的录音版本、角色/合作、位置或时长冲突。各视图独立检查输入，不从两个不足视图拼出一个合格候选。

来源事实的标题、署名、专辑、位置、录音、组、国家、总数或明确空值冲突保留双方来源和值，并使自动证据 unresolved；不同发行声明还会使所有权成为冲突。重新读取的精确拥有状态不以召回 ID 替代，删除、换绑、修订变化和查询失败使旧本地证据失效。所有权与“本次输入是否匹配”仍是两个结论；事实池不提交收藏。

测试覆盖真 library/store 入口的改名保护、同 ISRC 双目标、无绑定提示、完全无文本交集的精确补读，以及纯 matching 的版本/CV/合作冲突、可靠异写、明确空值、部分清单、旧修订和字段不拼接。Runner 已接入纯本地分流及远程输入优先筛选、兼容 track 偏好和统一提交路径。

## Runner 纯本地分流

`PrepareLocalExisting` 先消费本次完整 profile 与本地事实池。只有输入包含可识别目标专辑、相关目标证据充分、当前精确绑定有效、完整发行清单排除位置歧义且未截断时，才准备单行 `skip_existing`。当前用户名称可与同一精确位置建立证据关系，但不复制到候选或上游快照；专辑改名不能把同发行其他位置判成“另一个专辑”，同录音别名也不能掩盖重复位置。

多个相容本地目标须属于同一实际本地组、同内容且无位置歧义，再沿用总曲数/国家/稳定身份偏好；显式其他专辑、版本或位置优先，未知竞争事实不被丢弃。准备完成时核对证据使用的 track/release 修订，提交继续使用既有 skip 事务重验。

纯本地充分结果记录已存在跳过，不新增或修改收藏，不触发 library/enrichment；稀疏快照、无专辑、未绑定文本、未知清单或冲突继续上游检索，本地读取错误按失败处理，不伪装为未匹配。没有历史导入批次也能识别。`importer/local_existing_test.go` 验证真实 Runner 请求计数和逐行目标，`library/local_existing_test.go` 验证无收藏写入及修订/回滚边界。远程查询无结果后重新合入本地事实，也不能绕过专辑充分和清单位置唯一要求；远程返回已有 track 时仍检查已知清单中的未收藏竞争位置。

## 输入优先筛选

`SelectCandidate` 要求当前版本的完整输入 profile，不以 HighConf 授权。先比较歌曲、专辑/发行限定及位置；明确不符候选保留人工列表，但不请求资料、不参与自动竞争。未知竞争者按来源批量补必要资料，部分清单、unsupported、错误及取消不能制造唯一目标。实际来源解析后的精确目标合一，原始精确候选与新事实分别保留，摘要改变名称/归组等事实后重新比较冲突。

特典 CD 的区分性截断可排除合集；合集输入选择合集；无专辑仍跨组则复核。尾部省略号标题仍按可能截断保守处理，即使双方原文相同也不升级为完整名称。Runner 保存展开候选和结构化原因，提交核对处理起始修订，迟到结果不能覆盖新复核状态。

`input_priority_test.go` 验证真实 Runner 两版目标；`decision_replay_test.go` 使用真实 MusicBrainz 适配器及 httptest，验证第二碟、重复位置、部分清单、必要请求失败、同发行一次请求和输入修订。普通 App 回归默认拦截外部 HTTP，只允许数字回环地址或明确 replay；意外请求使整包失败。真实来源测试仍须显式环境开关。

## 兼容候选的默认偏好

先验证剩余候选同组、同录音且名称/署名版本相容、同发行没有多个 track 位置，再按已收藏精确 track、已有具体发行、已知总曲数、已知非世界国家、稳定来源/发行/track 顺序选择。已收藏状态只决定相容子集内的偏好，不能排除未知竞争者或覆盖显式 Deluxe/其他专辑/位置要求。

总数仅为实际优先子集补取：一个已收藏候选不为其他未收藏发行补摘要；多个已收藏目标仍按总数/国家/稳定顺序选一个，提交返回已有而非新增。跨组、不同内容或重复位置在总数请求前复核。说明使用 `prefer_owned_compatible_track` / `prefer_existing_compatible_release`，不称为客观身份等价。

## 自动结果与人工选择

本地充分证据和远程选版共用 `prepareAutomaticTarget`：已收藏目标按决策中读取的绑定修订准备轻量 skip 计划；未收藏目标沿用既有准入和发行成员确认。`SelectCandidate` 在补资料前读取输入修订，旧修订不能在计划准备时被刷新为新的授权。Runner 共用一个提交/日志/通知分支，结果为 Existing 时记录已存在跳过，不发 library 通知、不触发补全。

人工 `PrepareCandidate`/App 接受不使用默认选版：用户明确选择同组另一发行时仍保留该 track，要求新增发行确认，不被自动的已收藏优先替换。任务 5–8 的多来源问题和重评仍未实现。

## 名称、版本与署名

1. 完整名称的 NFKC、大小写、假名、空白和标点规范化可得到 `exact`；空值不能。相同未知注释原文可比较，但不能仅靠剥离不同未知注释证明等价。
2. 明示译名、原名、读音和带来源出处的别名可产生 `verified_alias`。无提示跨文字括号只保存备选，必须完整共同主体和独立的其他字段证据成立才提升；三项未验证备选不可循环互证。
3. 未知注释、无共同证据的纯译名、模糊相似不授予自动资格。不得将查询变体冒充上游别名，也不得把输入译名写入来源快照。
4. `(Vocal) Song` 和 `Song(Vocal)` 的 Vocal 为普通人声描述，不等同于 Off Vocal。
5. 版本在信息丢失前提取，保存类型、完整负载和原文。Remix 作者、Live 场次、重录/重制年份、限定版子型号、国家和载体不能只比较关键词。未识别写法保持保守，不按歌曲名称特判。
6. 角色与 CV、明确合作成员分别比较。相同声优不授权跨角色；发行署名或团体成员关系需要明确来源、对应专辑和已验证位置才能解释差异，不能覆盖明确的角色或合作冲突。

## 数值与自动证据

- 导入 profile 区分 missing / known / invalid，原始行不修改。时长支持 `mm:ss`、`hh:mm:ss`、明确的秒/毫秒后缀及表头单位；无单位纯数字不按数量级猜作身份事实。旧 `ParseDuration` 的宽松工具行为不用于新映射证据。
- 位置必须正整数，可读取有效 `n/总数`；碟号缺失不补 1。一般年份只作语义未指定的旁证，不能混用首次发行年与再版年决定身份。
- 时长比较独立于 relevance：差 ≤3000ms 为支持，>3000 且 ≤10000ms 为弱相容，>10000ms 为冲突。支持与弱相容不等于 exact，也不能构造输入等价键。
- 精度最多补偿秒级表示的半单位舍入，不按歌曲长短放宽，不接受任意大精度扩大容差。
- 自动候选要求可靠曲名及署名/专辑正证据，明确输入不能有未解释冲突；目标专辑与位置资料不足仍 unresolved。
- 截断只记 `compatible_truncation`。专辑截断当前采用至少 12 个规范化字符、完整目标的 70% 以上前缀，并要求可靠歌曲/署名、完整专辑资料、已验证位置及相同发行限定。短通用前缀或限定尾部不明仍复核；即使通过也须继续检查其他竞争者。

## 活跃问题等价证明（5.1）

`matching.ProveProblem` 提供强文本和精确 track 两条证明，不读取历史输入选择。文本路径要求可靠非空歌曲/署名/专辑、完整版本负载、相同数值要求及缺失掩码；等值时长格式可比较，但 3 秒容差不构成等价。原文、所有候选事实和规则版本纳入证据摘要。

`ProblemAnchor` 保存当前成员的完整证据；新成员加入时重证整个集合并取所有成员共同名称证据，不对别名集合做传递闭包。身份路径重新检查每行的完整当前候选范围，禁止以已收藏/总数默认偏好或候选集合重叠当作唯一身份；不同输入提供的同一 ID 事实互相冲突也拒绝。

`store.FindProblemCandidates` 只在活跃、当前规则问题中按名称/已证明身份召回，支持游标分页并明确截断。检索命中不是归并许可，仍须在写事务重新证明。5.2 已将证明接入复核/失败事务，自动建立/加入问题；重试保持成员修订，单行终态解除自身成员，最后成员结束才关闭。原始行和独立失败/候选不合并删除，前端问题展示、多行操作仍待后续任务。

## 存储边界与验证

`import_item.input_profile` 保存完整 JSON，文件导入经 App → Store → Runner 传递；无 profile 的内部调用由已明确单位的映射值构造，不猜原始列。当前新库代际为 `track-identity-v9`；v8 及更早代际拒绝打开，不自动迁移或删除数据。整数修订、问题、成员与交互租约约束见 [store 结构说明](../store/README.md)；语义归并及问题生命周期已接入，后台重评和完整问题界面仍待后续。

`LocalRecall` 是 matching 消费侧的批量事实契约；store 的独立派生索引覆盖当前值、有效绑定快照、角色和一跳关系，返回各层事实与修订、显式截断状态，不授权拥有或自动跳过。`RecallTextForms` 仅提供召回键，不能替代完整 profile 的限定/冲突检查。索引重建与召回不读取历史输入选择；4.4 已连接输入优先筛选，后续偏好/问题生命周期单独验证。

定向验证：

```sh
go test ./internal/matching ./internal/importer ./internal/lyrics
```

测试包括 unknown/conflict/truncation 的区分、可靠异写与反例、完整版本负载、角色/合作保护、原始行及解析状态持久化、relevance 与时长独立、未知竞争者保留。`internal/app/identity_admission_test.go` 验证真实准备入口的身份展开、已有目标及 seed 拒绝；自动目标由 Runner/library 真实入口测试验证。历史十行 `TestCSVSearchDisplayRegression` 仅保留展示基线，不代表导入新增统计；`Engine.Decision` 的旧分类也不能代替真实终态验收。多行问题事务仍需后续集成验证。
