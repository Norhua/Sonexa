# 歌单消费能力

`playlists.Provider` 由业务声明，只依赖 `provider.Upstream`，不要求元数据、封面或歌词能力。具体平台解释链接、原生字段、分页和错误；业务、存储、绑定不构造平台请求或启动 Python。集合构造拒绝重复身份，来源列表和请求查找使用同一登记；运行环境不可用通过来源可用性报告，不伪装为空歌单。

## 快照契约

- `Ref` 为平台及规范歌单 ID；`Entry.TrackRef` 为平台歌曲身份，不是本地元数据绑定。
- `EntryKey` 区分同曲出现。适配器在没有稳定原生条目 ID 时按歌曲 Ref + 出现序号生成，位置只是顺序。
- 基础字段用 nil 表示未知，已知空值保留空；署名保持原顺序，毫秒时长不默认造 0。
- `Completeness` 同时保存声明总数、原始项数、普通歌曲数、明确排除数与页数。来源必须证明完整，业务 `Validate` 再核对身份、计数/已知位置覆盖、出现键唯一、顺序及大小上限；零项只有明确完整零总数才有效。
- `Excluded` 可携带 `TrackRef/Reason`；上游只报告稳定身份与数量、不提供原始位置时 `Position=0`，不得伪造位置。无位置也无身份的排除项拒绝。首次绑定不导入排除项；`Diff` 根据通用 `TrackRef` 保护该身份的全部已有出现项，维持原状态/字段/需求，不因暂时过滤生成删除、不自动恢复缺席或忽略。没有平台分发。后续可读时按原键复用；后续明确缺席且无过滤保护时正常执行删除策略。
- 错误统一为 input/access/restricted/incomplete/temporary/cancelled/runtime_unavailable/resource，只交付可展示的脱敏诊断。失败不交付可提交的部分快照。

当前应用已登记 QQ/Spotify 歌单能力，QQ 与其他能力共享实例；Spotify 运行环境缺失时仅标记该来源不可用。App 长期持有 Fetcher，限制总并发 2、同源 1，设置换集合不重建池，关闭取消排队/在途工作后等待退出。

## 数据与导入需求存储

新库代际为 `streaming-playlists-v2`。旧代际直接拒绝打开，不转换或自动清理历史数据。

| 表 | 责任与约束 |
| --- | --- |
| `synced_playlist` | 平台 + 规范 ID 唯一；保存上游名、别名、修订、获取/确认时间、摘要、完整性与排除项。不存分享链接。 |
| `synced_playlist_entry` | 歌单 + 出现键唯一；保留顺序和最新基础信息；同 track 可有多个出现。`imported` 必须引用有效 track，`pending/ignored` 不得有 track。只有 imported 可以上游缺席。track FK 使用 RESTRICT，禁止直接物理删除破坏同步关联。 |
| `import_batch` | 文件来源固定 `file → library`；同步为 `synced_playlist → synced_playlist`，保存创建时目标显示摘要；filename 始终为空。统计分母来自实际保存的输入，不因撤销需求缩小。 |
| `import_item` | 每次尝试的原始列与映射字段不可改写；`merged_item_id` 指向共享调度主条目，合并输入始终保留在原批次。 |
| `import_destination` | 每个输入自己的目标和 active/delivered/cancelled 状态、修订及显示摘要；一个同步出现最多有一个活动尝试。删除条目前在同一事务撤销并断开目标 FK。历史摘要用于审计。 |

`pending` 包括 queued/matching/review/failed，具体任务状态仍由导入队列保存。
`ignored` 不应有活动需求，恢复须用最新已确认快照建立新输入，而不是复活旧 discarded/merged。
`imported` 的可见性由有效 track 引用决定，不由任务的 imported/skipped 名称决定。
当前由 `playlists.Service` 保留完整计划，`store.ApplyPlaylist` 执行绑定/刷新事务；
导入接受、无需匹配、自动/手动重复跳过和离线整理共用 `deliverImportTx`，所有有效同步引用与确认关系同事务提交。
主任务移出共用 `discardImportTx`，同步目标进入 ignored，文件目标取消；恢复只创建所选目标的新尝试。

活动证据只读取 active 目标的输入。撤销主输入目标但存在其他需求时，主条目保留为调度壳；
按输入 ID 选择仍有效的确定性代表，仅在返回值覆盖匹配字段，不改持久化原文。
原始内容聚合仍保留全部历史输入，已保存的手动搜索来源/候选/草稿不被清除；目标变化递增修订，拒绝旧搜索结果。
全部目标消失才将主条目置 discarded；被吸收输入保持 merged，不重复累计移出，不继续出现在复核队列。
历史终态记录用于审计、确认与原批次统计，不是新的活动需求。

### 本地实体与音乐库范围

`track` 存在表示本地实体，不等于收藏。SQL 无 in_library 默认值；低层创建输入显式指定归属，
普通本地创建明确入库，准入新建从持久化有效需求决定：有 library 目标才入库，仅同步不入库。
`created_at` 表示创建时间；`library_added_at` 为首次入库时间，从未入库为 NULL，取消/再次入库保留首次时间。
Track/TrackView/详情分别投影两种时间；跨前端时间为 RFC3339，未有首次时间的 AddedAt 为空。

`track_read` 与 FTS 内容保留所有本地 track，身份判重、详情、编辑、补全和真实结构引用不得按音乐库过滤。
音乐库列表/计数/最近添加/艺术家与专辑展示均限定 in_library；`ListSyncedTracks` 专用查询保留 imported 出现及缺席项。
FTS 在 SQL 查询内施加作用域后再限量，内部身份与结构读模型不复用音乐库过滤。
`ReleaseStructureTracks` 专用于编辑目标影响，`ListLibraryGroupReleases` 和展示代表仅用于音乐库。

显式批量入库计划按 track ID 去重，提交重读当前状态：并发已入库计 already，物理删除为 stale 并整批不写入。
track ID 不复用，旧计划不会命中新实体；归属操作不重建曲目或重置首次时间。
普通集合后端逐项验证已入库，非法混合整批拒绝；既有所有导出范围同样排除未入库曲目。
`RemoveFromLibrary` 清理普通集合但保护同步引用；`DeleteSyncedPlaylist` 撤销自身需求并仅回收无剩余引用的未入库曲目。
发行 orphan 查询始终检查全 track，歌词按真实文件引用回收，仍有引用的封面采用/文件记录保留。
这些后端入口、同步 UI 和 App 生命周期已接入；平台发行包及原生验收仍独立跟踪。

## 差异与确认

差异按出现键比较，不按标题/列表位置；插入首项、改名和重排不重导旧项。同曲副本按 Ref + 出现序号配对，
不能识别未观察区间内的删后重加。当前上游项按新位置排列，已导入缺席项按旧位置和本地 ID 稳定排列。
同步实体 ID 不复用，避免删除再建后旧计划误命中新实体。

- 绑定/刷新网络获取在数据库事务和服务锁外，规范身份重复抓取或已有待确认计划明确拒绝。
- 服务端计划 15 分钟有效；合计最多 8 个准备/待确认操作，保守计量最多 64 MiB，不驱逐其他未确认预览。
- 前端只能取得展示差异、token/hash，不能提交自造快照。计划哈希只序列化类型化业务值，不解码上游响应。
- 确认原子更新快照、顺序、名称、忽略恢复、输入/目标和修订；预览/取消/不完整结果没有持久化副作用。
- 忽略区包含仍在上游的 ignored 项，无增删也可选择恢复；非法或重复恢复 ID 整批拒绝。未选择项不变。
- 重复成功提交返回同一结果；存储失败整体回滚并可重试原计划，目标变化导致 stale 则需取消并重新读取。
- 接受先提交会递增歌单修订，使旧删除预览失效；同步先删除会撤销需求，旧接受/搜索/失败重试不能复活。
- 关闭取消读取并等待服务工作完成；提交前再次检查 context，取消不能提交半份快照。

结果投递封存有效目标集合及输入/目标/条目/歌单修订，并在精确身份短路之前重验。
新建仅同步曲目不入库；可靠复用现有 track 永不隐式入库（包括文件输入命中同步 track）。
Runner 在提交后的需求变化通知中取消已失效的在途匹配，有剩余目标则回队后按有效代表输入重新执行。
原批次统计按输入目标记移出，被吸收输入维持 merged；真实调度状态与目标统计分开，不能用移出计数停止其他歌单工作。
