# QQ 音乐上游

元数据、封面、歌词及公开歌单由同一 Provider 提供，复用请求客户端与 QQ 平台桶。

## 公开歌单读取

使用固定 `musicu.fcg` 的 `music.srfDissInfo.DissInfo / CgiGetDiss`，请求 `disstid / song_begin / song_num`，每页 100 项。沿用既有 musicu envelope 和请求块 code 校验。首次获取与刷新都使用 `NoStore`，不读写响应缓存；链接只解析规范 ID，从不直接请求用户 URL。

输入限制为数字 ID 或 `y.qq.com` 的明确歌单详情路径，包括 ryqq playlist、taoge 和旧 playlist.html 分享形态。拒绝错误主机、用户信息、非默认端口、非歌单路径、非法数字与冲突身份参数；不复制 demo 的“寻找任意长数字”兜底。

当前采用的严格响应字段为 `dirinfo.title / disstid（或 dirinfo.id）/ total_song_num / songlist`。逐页核对身份、总数、原始页长与重复页；缺身份、未知总数、缺列表、提前空页、总数/名称变化或未知歌曲身份使整轮失败。明确零总数与空列表是成功空歌单。歌曲兼容该端点新旧 `mid/songmid`、`name/songname`、专辑字段，未知基础信息保持 nil，署名保持顺序，秒转毫秒。

不使用 qzone/v8 或任何异常触发的端点轮换；HTTP 鉴权/限流和非零业务 code 立即停止。临时 HTTP 错误最多两次额外尝试；所有发送共用原 QQ 桶、动态门禁和 500 次预算，总期限 15 分钟、最多 200 页/20,000 项，并限制累计响应字节。

成员键为歌曲 Ref + 出现序号，重排不改变出现身份；相同歌曲两个副本之间不能判断具体删除了哪个。缺字段不生成占位，不把 QQ 歌曲 Ref 当作已接受的元数据绑定。

**验证边界：** 新端点形态来自 demo 协议参考，离线 HTTP fixture 验证严格解析及失败保护；尚无本变更授权的真实歌单读取证据。若真实响应与此契约不同，先停止并核对协议，不能宽泛回退以制造成功。既有元数据/歌词在线样本不证明歌单已验收。
