# Sonexa 的 XLRC 统一歌词

## 参考与范围

参考 [Boof2015/xlrc](https://github.com/Boof2015/xlrc) 的 `SPEC.md` 0.1-draft，审阅提交 `01569cc5b0037a7ba562ba15de9b945dd47197cf`。规格为 CC0 1.0，Go 实现独立编写，未复制参考 TypeScript 源码、整首歌词或引入其运行时依赖。

`Build` 是无额外推断的构建入口；三来源适配器返回前调用 `BuildOnline(input, "zh")`，显式开启下述在线关联/语言规则。两者成功均输出 `Document.Format=xlrc`；`Document.Text` 是唯一采用对象。`ParseXLRC` 处理 XLRC 本地输入；`ParseText` 仍保留 TXT/LRC 的 BOM/换行之外原文，并识别行首 `[xlrc:]` / `[>...]`。本地 `.xlrc` 始终使用 XLRC 解析器。非法控制标记、越界时间、NUL/非 UTF-8、超限会拒绝采用，不像参考浏览器解析器那样跳过损坏行后交付残缺文档。

## 支持的标准语义

- `[ti:]` / `[ar:]` / `[al:]` / `[by:]` / `[length:]` / `[lang:]` / `[langs:]` / `[offset:]` / `[xlrc:0.1]`；未知元信息保留，不用其推断正文类型。
- 毫秒整数时间，接受 1–3 位小数、多个行首时间戳；输出 3 位小数（参考实现同样支持），不将原生毫秒四舍五入为百分秒。
- 行首时间后 `[v:任意标签]` 表达人声归属。未标注不推测；同刻不同标签保留为不同原文行，翻译继承父行人声。不会从候选歌手名单、`男：` 等普通文字生成标签。
- `汉字[假名]` 保存 ruby，范围是正文中的 **Unicode 码点** `[start,end)`，不是 UTF-8 字节或 UTF-16 索引；与逐字片段并存。混合汉字/假名基底、非假名括号保留字面文字。支持假名注音，不宣称将任意拼音/汉字谐音自动转为 ruby。
- `[>BCP47]正文` 从属于紧前的原文，继承行首时间和人声。支持多个语言、同语言多行、原文多时间戳展开。显式父关系在排序前建立；同刻多原文仍能保留正确关系。无父关系默认只按唯一时间/±10 ms 规则关联；在线适配器可显式开启下述有诊断的近邻启发式，不把推测描述成上游明确关系。
- `Latn` script 子标签表示罗马音阅读类别；其他语种为翻译。解析器不检测语言；通用未知标签仍为翻译 `und`、罗马音 `und-Latn`、附加文字 `und-x-additional`。三来源在线转换按下节补全翻译/罗马音语言，不改本地导入的语言或原文头。
- 逐行/逐字混合、空计时行和尾部清屏时间保留。词结束仅来自显式事实，不以后一词开始推造。

## 在线关联与语言补全

`BuildOnline` 只由来源适配器调用，复用公共解析/排序/offset/精度/序列化流水线；业务评分和前端不运行第二轮关联，`Build` / `ParseText` / `ParseXLRC` 不开启新增推断。

1. **近邻关联 `time-nearby-v1`**：先验证显式 ParentID，再执行精确/±10 ms 精度规则。对仍未关联的 available 翻译/罗马音非空计时行，在共同 offset 轴上选择 **闭区间 ±2000 ms 内唯一最近** 的非空原文行。等距（含同刻多声部）、竞争同一父行、父行已被本通道明确/精确关联占用、声部冲突、越过本通道前后计时行（包括空行）、新行首晚于真实行结束时拒绝。不是无界全曲索引配对，也不生成译文或验证语义相等。
2. 只调整附加行首，原文、真实词起止和行结束不变。诊断 `time_nearby_alignment` 保存规则、数量、规范化行位置与共同输出轴上的调整前后时间（含全局 offset），卡片显示「启发式对齐」并提示可能误判。诊断属于完整文档，不写入 XLRC；文件中的从属关系回读后直接继承，不再猜配。保持二分/线性规模和现有诊断/投影上限。
3. 接受的行紧跟原文输出 `[>语言]`，没有自己的行首时间戳；真实逐字时间仍保留。无时间、明确 Independent、unknown/additional、超出范围或歧义等未接受行继续保留 `x-channel` 和原时间，不以“全部挂接”为由删字。
4. **语言只补全附加行**：非 `und` 的明确语言优先。有限文字规则要求至少两个假名/谚文字母且占该行字母至少 20%，不与另一类/其他文字字母冲突，分别返回 `ja`/`ko`（允许汉字和拉丁混排）；不是通用语种识别器。纯汉字、纯拉丁及其余不确定文字不据此猜语言。翻译未知时使用适配器明确传入的 `zh`，不声称识别出简繁或经上游确认。
5. 罗马音从已关联原文的明确语言或上述文字证据获取基础语言；该行不确定时，可用全曲无冲突的已知基础语言，出现日/韩等冲突则不做全曲回退。追加 `-Latn`（如 `ja-Latn`/`ko-Latn`/明确中文的 `zh-Latn`），不能把原脚本拼成 `zh-Hans-Latn`。仍无法判断时保留 `und-Latn`，不把拉丁字母误认英语，不默认罗马音为中文。
6. 推断在原文副本判定后执行，只改构建器拥有的副本；不让新增默认标签把原文副本、未知/谐音内容提升为确认翻译/罗马音，不改变存在性加分、声部/ruby 或歌词正文。

## Sonexa 保真扩展 v1

草案无法独立表达未同步正文、不同步附加轨、原生行结束及语法相似的字面文字。因此规范化输出带 `[xlrc:0.1]` 和 `[x-sonexa:1]`。这些扩展不是上游 XLRC 标准承诺；第三方草案解析器可能忽略扩展，不能保证保真回读，Sonexa 的解析器支持完整往返。

| 语法 | 语义 |
| --- | --- |
| `[x-text]正文` | 没有行首时间，不填 0；保留空白及空正文行 |
| `[x-channel:translation:und]` | 切换独立附加轨，随后带时间或 x-text 的行保留自己的时间，不成为原文，也不再次按邻近时间挂接 |
| `[x-channel:romanization:und-Latn]` / `[x-channel:additional:und-x-additional]` | 同上，区分已确认罗马音与未知附加文本；支持原文 `original` 轨切换 |
| `[x-end:毫秒]` | 位于可选人声后、正文前，保存真实行结束时间；从属行也可用 |
| `[x-role:translation]` | 紧随从属语言标签，只在明确的角色与语言 script 推导不一致时输出；也可取 romanization/additional，不能把从属行指定为 original |
| `\\` / `\[` / `\<` | v1 字面转义，只解这三类；保留看起来像时间/ruby/通道控制的真实文字。不带 x-sonexa 标记的标准文件不解反斜杠 |
| 连续/尾随 `<mm:ss.xxx>` | 沿用 Sonexa 增强 LRC：尾随或连续标签中的前一个是显式词结束。相邻词即使结束=开始也输出两个标签，不能省略事实；没有显式结束不补 |

示例（独立构造）：

```text
[xlrc:0.1]
[x-sonexa:1]
[lang:ja]
[00:01.005][v:A][x-end:3000]<00:01.005>私[わたし]<00:01.500><00:02.000>が
[>en]I
[>ja-Latn]watashi ga
[00:01.005][v:B]君[きみ]
[>en]You
[x-channel:translation:und]
[00:05.000]无法挂接的独立译文
[x-channel:additional:und-x-additional]
[x-text]未分类谐音
```

## 交付与保存

- 原文/附加轨保留行词时间、ruby、人声、语言、内部 ID/ParentID；显式父关系须存在，且时间/人声不能矛盾。`Independent` 防止保存回读后把独立轨重新猜配。ID 为文档内部身份，不写成上游歌曲 ID。
- `Rows.Annotations` 保留每条从属文本的角色、语言和 ruby；旧 `Translation` / `Romanization` 字符串投影仍供简单消费者使用。阅读视图按后端关联显示，多语言不合并丢失；采用始终保存全文，不仅保存下拉所选通道。
- 所有返回轨共用同一等价 offset 轴；负实际时间通过全局 offset 保留。原文与真实词/行结束不随附加行精度/近邻对齐移动。
- 2 MiB 文本/投影、24 小时时间、32 MiB 单会话/128 MiB 进程限额继续有效，新增 ruby/关联/注释参与内存计账；文档 seal 覆盖新字段，消费侧只验不修。
- 文件仍为 UTF-8 不可变内容哈希文件；包含 XLRC 标记/从属行的内容存为 `.xlrc`，旧 TXT/LRC 保存约定不自动迁移。无需数据库通道表，不自动清库或重写历史歌词。

## 上游能力限制

QQ、网易云、酷狗在各自适配器解释 QRC/YRC/KRC 后调用 `BuildOnline(input, "zh")` 交付 XLRC。网易 v1 请求包含 `ytv/yrv`，读取实际字段 `ytlrc/yromalrc`，随实际选择的 YRC 或普通 LRC 优先取配套附加通道；普通端点回退优先自己的附加轨，缺失/损坏时才保留另一套可用文字。QQ 真正相邻词结束与原生行结束均保留。酷狗 language 行数匹配时保存明确父行（含空行和同刻不同原文）；type=0 音节数也匹配词数时保留原生词时间，否则不猜，行数不符只保留未同步文字。未知类型保留为 additional。三来源均不保证实际接口提供语言/声部/ruby；语言缺失按上述有限规则补全，声部/ruby 仍只保留明确标签。

酷我因信息不足已移除，其端点、两层内嵌翻译猜测、专用配额不再是生产能力。
