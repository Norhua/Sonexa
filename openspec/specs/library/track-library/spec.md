# library/track-library Specification

## Purpose

管理不依赖本地音频文件的音乐收藏。曲名为必填，其他信息允许缺失；曲目与共享歌集分别保存，通过统一的候选入库方式、明确的字段归属和删除范围保持数据一致。

## 当前限制

自动写入未完整保护用户锁，候选字段映射和灰色行归属有遗漏，见 [G01、G02、G06](../../../known-gaps.md)。

## Requirements

### Requirement: 曲目与歌集字段
曲目 SHALL 保存曲名、署名、位置、时长、风格、注释、歌词、匹配身份及补全状态。歌集保存标题、署名、发行类型、日期、碟数、音轨数、载体、国家、厂牌、目录号及封面。列表从关联歌集读取专辑名和年份。

#### Scenario: 基本信息入库
- **WHEN** 用户对复核条目选择无需匹配
- **THEN** 按原始曲名、艺术家和专辑创建曲目，匹配身份为空，其他详细字段可空；缺少曲名则拒绝创建

### Requirement: 统一候选入库
导入自动入库、搜索加入、复核接受和灰色行加入 SHALL 共用候选存储入口，只写传入候选的已知字段，不使用查询或导入文本补齐上游缺失值。搜索加入与复核接受不等待详情请求。

#### Scenario: 不同入口接受相同候选
- **WHEN** 同一完整候选经导入、搜索或复核入库
- **THEN** 除本地标识和时间外，曲目及歌集字段一致；有发行标识的曲目进入待补全状态

#### Scenario: 候选字段缺失
- **WHEN** 候选没有艺术家而导入行有艺术家
- **THEN** 曲目艺术家仍为空，原始值仅保存在导入条目

### Requirement: 来源与用户编辑
曲目和歌集 SHALL 分别保存逐字段来源与锁；手动编辑记录 user 来源并加锁，明确采用上游值时记录对应来源并解除该字段锁。缺少来源记录按未知处理，界面用歌集徽标说明共享影响范围。

#### Scenario: 保存手动修改
- **WHEN** 用户手动修改风格并保存
- **THEN** 风格及 user 来源、锁一起保存；自动补全保护限制见 G01

### Requirement: 缺失值与删除
未知字段 SHALL 使用缺失值，界面显示短横线，导出保持为空。删除曲目清理其组织关系与艺术家关联，并保留上游清单。

#### Scenario: 删除后清单仍可浏览
- **WHEN** 用户删除已收藏的某个清单位置
- **THEN** 该位置回到灰色行，其他收藏和清单数据不变
