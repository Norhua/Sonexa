## D01：取消目标说明与常驻来源诊断区

### 原规格/设计

- [主规格](../../../specs/upstream/lyrics-search/spec.md)和 [change delta](../specs/upstream/lyrics-search/spec.md)的「双栏搜索与分来源状态」要求各来源独立显示无结果、失败原因与重试。
- delta 的「候选不再按来源聚合」场景仍要求分来源进度可见；[design.md](../design.md) §1.3、§4 约定单独来源状态区展示阶段、结果数和预取成功/失败/未完成计数。
- 旧实现额外在搜索条件上方显示「目标：曲名 · 仅修改当前歌曲的歌词」，并把来源错误原文放在常驻诊断区。

### 当前实现与归档规则

- 歌词搜索 SHALL 不显示顶部「目标…」说明，不提供独立的来源进度/计数/报错滚动区域。
- 来源选择旁仅显示紧凑的进行中图标（含可访问阶段说明）或单来源重试图标；重试仍使用已提交查询快照，只替换该来源，不清空其他来源预览或人工选择。
- 自动来源搜索/预取失败 SHALL NOT 直接渲染错误原文或弹出逐来源错误提示，不影响其余候选。内部状态、错误类别、预算及取消语义不变。
- 左侧无候选时使用已有空间展示简短空态：未搜索、搜索中、全部成功但无匹配歌曲、包含失败的未完成搜索互相区分。存在失败时不声称所有来源都无匹配歌曲；保留来源重试入口。
- 无效输入、初始化、预览确认及采用失败仅给出面向用户的简短可恢复反馈，使用可关闭悬浮提示，不增加文档流高度。取词失败使用无正文预览区的简短状态及手动获取入口，不直接显示技术错误。成功采用通知也不挤压候选/预览高度。
- 取消「目标」文字不改变固定目标/修订校验：仍仅修改打开时当前歌曲的歌词，不采用曲名、艺术家或绑定。

### 归档需调整的场景

1. **单来源失败**：保留其他来源候选和所选预览；没有常驻错误全文，来源旁可独立重试。
2. **候选不再按来源聚合**：继续按综合分跨源排列；将「分来源进度与重试仍可见」限定为紧凑活动图标与重试，不要求额外计数区域。
3. **无结果与错误区分**：只有全部搜索成功且无候选才显示无匹配歌曲；包含失败且无候选显示简短重试指引。
4. **操作失败反馈**：反馈不占用额外布局高度，不暴露内部路径、上游错误码/错误全文；失败不授予采用权限、不修改已有歌词。

## D02：曲目元信息只放左侧卡片，预览不再铺开诊断

### 原规格/设计

主规格及 delta 的「双栏搜索与分来源状态」「通道状态与合并正文」，以及 QQ/YRC/KRC 回退场景中，存在「右栏提供通道状态和警告」「失败附警告」「显示逐字失败」等直接展示要求。旧实现右侧重复显示曲名、艺术家、格式、翻译/罗马音摘要、逐字状态、启发式依据及全部 `document.warnings`。

### 当前实现与归档规则

- 右侧歌词预览 SHALL 不重复显示曲名、艺术家、类型与通道摘要，也不直接遍历展示文档警告或原始技术错误。
- 左侧卡片继续显示曲名、艺术家、专辑、来源、时长、匹配/综合分及明细、实际格式、获取状态、翻译和罗马音徽标。徽标保留有/未提供/待检查/获取中/失败/无法确认及部分、未同步、启发式说明，已有通用启发式依据保留在卡片提示中。
- 后端完整文档、通道/逐字状态与诊断仍原样保留，解析失败不当作上游未提供；只是取消右侧的独立逐字状态行与警告全文，不改变内容保留、内容评分、回退或采用条件。
- 预览内容顶部只保留阅读/原始文本模式操作、同一工具栏靠右的「额外展示」下拉，以及有非零 offset 时用于核对时间的偏移说明。歌词正文中真实存在的曲名/署名行不按文案删除，本次移除的是界面重复元信息。

### 归档同步注意

- 调整上述歌词搜索条款的「警告展示」语义为内部诊断保留、候选简短状态与必要操作反馈；不再强制在正文上方展示警告。
- [QQ delta](../specs/upstream/qqmusic/spec.md)及主 QQ 规格关于回退警告/逐字失败的 UI 措辞应引用歌词搜索的统一呈现规则，不能重新要求在预览顶部长篇展示；解码、失败分类与回退安全约束一字不放宽。
- 无需改变 provider-registry 的能力/错误交付契约；错误归一化与返回不等于必须把错误全文放到页面上。

## D03：三列阅读与所选附加通道

### 原规格/设计

- delta「可读歌词预览与原始文本分离」：时间独立一列，可对齐翻译/罗马音附在原文下。
- design §4：两列为时间和正文，两种附加通道同时以次级样式显示在正文下方。

### 当前实现与归档规则

- 阅读预览 SHALL 使用三列：时间、歌词原文、当前选中的翻译或罗马音；时间为窄列，正文与附加文本分别换行，长行不撑开预览。
- 右侧预览内容顶部提供可键盘操作的「额外展示」下拉，与「阅读 / 原始文本」同一工具栏靠右，选项为「翻译 / 罗马音」，不再放在搜索来源区。无预览文档时不显示该控件。默认选翻译，切换候选/重新搜索保留本次窗口的选择，关闭后重开恢复翻译。
- 此条按 `0c5fc849` 后续提示修正，替代上一轮的「搜索控件区右侧」「歌词 / 罗马音」约定；上一轮缘由和任务原文保留，不追改历史。
- 原文始终显示，第三列仅显示所选通道；缺失时对应单元格为空，不复制原文、不生成翻译/音译，也不自动替换为另一通道。
- 仅消费后端已交付的 `Document.rows` 关联：可靠关联的多行附加文字放在同一行第三列；未关联的所选通道保持独立行、保留自己的时间，第二列留空并注明通道/独立行；无时间显示 `—` 和未同步说明，不能按数组下标或最近时间猜配。
- 归属未确认的 `additional` 文字在第三列独立保留，并明确标注「附加文本（归属未确认）」，不冒充翻译或罗马音；切换时仍可查看。
- 下拉与阅读/原始文本模式切换 SHALL 只改变展示，不重新获取、不重新批准同版本、不改变综合分/选择/采用权限，不修改完整文档。原始文本始终显示全部有效通道和时间标签，采用仍原样使用后端同版本 `Document.Text`，不会只保存下拉所选通道。
- 普通文本、空白、段落、标点、Unicode 及 HTML 样式文字继续按文字保留，不执行 HTML。

### 归档需加入/修改的场景

1. **三列对齐**：原文同时含翻译与罗马音时，默认时间/原文/翻译同排；选择罗马音只替换第三列，原文与时间不变。
2. **独立附加行**：保留所选通道的独立时间和无时间行，不借原文时间伪造关联；未分类文字仍可查看。
3. **通道缺失**：选择不存在的通道后第三列为空，纯文本原文仍完整可读。
4. **切换不改变保存**：罗马音模式下采用仍保存包含翻译、罗马音、全部真实时间标签的完整规范化文本；切换不增加获取或同版本预览批准调用。
5. **窗口生命周期**：换候选保留所选附加通道；关闭并重开恢复默认翻译。

## U01：毫秒与百分秒精度差导致独立行（已定位，尚未修复）

此项是现有规则的局限，不是已实施的新对齐规则；归档不能把下面建议写成已实现。

### 当前统一化标准

- 来源适配器返回前将原生 QRC/YRC/KRC、LRC/TXT 转成 `lyricdoc.Document`：整型毫秒行/词结构、通道状态、阅读行和唯一最终采用文本；优先有效逐字原文，只选一套原文。公共工具由适配器调用，业务和前端不二次归类/合并。
- 在线多通道文本统一序列化为 TXT/LRC/增强型 LRC；LRC 的 1–3 位小数右补零转为毫秒，例如 `.74` 是 `740 ms`，不是 `74 ms`；QRC 毫秒原值保留。换格式不等于补足来源丢失的时间精度。
- 独立 offset 比较采用 `stamp - offset`，合并后输出等价的单一全局 offset，词起止不猜造；输出时间列与最终文本行标签一致。
- `internal/lyricdoc/merge.go` 在共同时间轴上按时间稳定排序；只在附加行时间与唯一非空原文行**完全相同**时关联。未匹配时保留附加行自己的时间，不进行最近邻/按行号匹配。该规则与原 design §3.1 一致，不是前端另写排序。
- 前端直接读取 `Document.rows` 的既有关联，原始模式和采用读取同一文档的完整 `Document.Text`。

### 截图现象与已验证原因

截图中原文/翻译依次为 `42.743 / 42.740`（差 3 ms）、`47.856 / 47.850`（差 6 ms）、`53.045 / 53.040`（差 5 ms）。不相等使精确关联失败，翻译独立行又因数值略小而排在原文之前。这不意味着选择了统一化前的 HTTP 正文，而是当前统一化**保留原值却没有精度容差对齐**。

QQ 适配器独立解析逐字原文与翻译/罗马音，`qrcToLRC` 保留毫秒，普通 LRC 解析右补零；这些差值符合百分秒量化/截断的形态。但本次没有取得截图所对应的原始上游响应，不能断言 QQ 原字段必然以两位小数返回或具体使用何种截断算法。

合成 `TestExactAlignmentKeepsSubCentisecondDifferences` 验证：完全相等可合并；3/6 ms 差值保持独立、按时间提前并附 `unaligned` 诊断，规范化文本仍含各自时间。测试只是锁定现状与原因，不代表该体验问题已解决。

### 建议的后续规则（待确认，不实施）

在来源返回完整文档前，以原文主时间轴为准处理**有界、唯一、单调的精度级关联**，例如先讨论不超过 10 ms 的容差，而非直接引入数百毫秒通用最近邻。需保护同刻多句、相邻密集行、不同断句和已有逐字时间；歧义/大偏移仍保留独立行。若改写附加行时间，应记录原时间和关联依据，并在后端一次构建结构、阅读行与最终采用文本，不能只在 Vue 中隐藏不同时间。容差范围、双向或截断区间、来源适用范围及保存策略须确认后再替代原精确匹配规则。

## 未改变的边界

本次仅改前端呈现与简短操作反馈，不改变后端协议、上游职责、通道识别、时间关联、排名公式、Top 3 预算、数据库、文件格式、修订/版本批准、详情页或其他搜索页面。主规格中的固定目标、失败不得采用、内容保真和安全要求继续有效。离线浏览器测试不代替真实上游与 Wails 原生窗口验收。
