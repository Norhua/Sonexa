## Goals / Non-Goals

**Goals:**
- 一处完整定义、一处引用：交互归 app-shell，独立即时保存归 track-editing，候选与通道归 lyrics-search，QQ 专有协议归 qqmusic，持久化归 data-store。
- 保留未受影响的需求与场景；清理记录后可通过 Git 和本变更追溯决定与验证边界。

**Non-Goals:**
- 不重新开发歌词功能，不修复无关测试，不改元数据评分、自动补全、导入来源、FTS、CSV/JSON 导出或数据库结构。
- 不将网易云 YRC、酷狗 KRC、本地二进制 QRC、播放器/实时高亮、独立歌词导出 UI 写成已实现。

## Decisions

1. **新增独立歌词能力而非扩张元数据来源表。** `internal/lyrics` 维护四来源，`bindings_lyrics.go` 管理有限会话，前端按来源创建会话并等待结果汇总；QQ 与元数据共享桶，网易云与 `cover-163` 共享桶，其他来源独立限流。相比分散塞入元数据各规格，这能明确候选不是身份、预览不是采用。WEAPI 使用 `internal/provider/netease` 的封面/歌词共享加密模块。
2. **复用比较、局部放宽准入并收紧自动预览。** `matching.DefaultWeights().ScoreCandidate` 保持不变，歌词层增加中文伴奏区分、同名近时长人工确认例外和时长降级；不把个人/团体署名等同作为全局匹配事实。
3. **会话不落原始响应缓存。** 搜索和预览仅留内存，关闭取消，30 分钟失效；采用复用 `StageLyrics / SaveLyrics` 的不可变文件、哈希、事务引用和修订检查。相比另建歌词表或把每个候选落盘，此方案不增加数据库结构或清理负担；user/follow 仍比较有效上游值，而非按歌词来源绑定。
4. **QQ 新旧链路隔离。** 手动歌词以 `GetPlayLyricInfo` 批量取 QRC 与普通 LRC，可选通道独立失败；原 `internal/provider/qqmusic` 详情补全仍按详情/旧端点。仅内置 `jixunmoe-go/qrc` 提交 `866e996416b0cec7bef648400633f6483c4200d5` 的 MIT 变体 DES 块变换，LICENSE/来源位于 `internal/lyrics/qrcdes/`；不使用其无界解压，不增加 go.mod 依赖。在线十六进制密文经有界解压和时间验证转换，不扩大到本地二进制导入。
5. **保留多通道内容，不编造同步。** 内存 DTO 区分未提供/失败/未接入；按时间而非下标合并，非同步附加文本也保存。最终合并 UTF-8 文本是采用对象，诊断及密文不入库。详情去标签与搜索原文预览分别表达，不能因 UI 隐藏而删文件内容。
6. **通过标准 delta 同步而非直接覆盖主 spec。** MODIFIED 保留每个既有场景；先验证 delta，取得 specs 指令快照后逐项合并，再做严格验证和需求一致性检查。文档索引、架构与验证记录同步更新，最后删除 `change_record`；原记录已在 Git 中，无需复制全部计划日志进主 spec。

## Risks / Trade-offs

- [非公开接口波动] → 只记录有实测证据的能力及失败处理，不承诺全部歌曲/任意时刻可用；旧计划观察过 QQ `2001`、酷我 `301`，在 known gaps 保留复测入口。
- [误将历史测试当作本次验证] → `verification.md` 分开本次离线核验与计划中的网络、Wails、浏览器结果；本次不新增原生人工验收结论。
- [既有 E2E 不稳定] → 保留第二次计划记录的 241/242 及编辑器用户徽标断言失败，不把它归因于歌词或声称已修复。
- [删除记录丢失调查结论] → 保留 D01–D08 对照及 Git 恢复命令；MusicBrainz 目标曲发行与 recording 均为空关系，不依据署名补造角色。
