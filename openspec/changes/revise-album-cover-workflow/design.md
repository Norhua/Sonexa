## Goals / Non-Goals

**Goals:**
- 用一个解析入口服务直接图片请求、预取、列表、详情和专辑，不再由前端决定下载 URL 或复刻选图规则。
- 将“某来源有哪张图/规格”“哪些规格已下载”“用户选了哪张图”分开建模；查询成功与下载成功不是同一个布尔值。
- 保持歌曲匹配身份、发行组代表选择、收藏数据及旧采用文件兼容；所有新写入可恢复、失败不破坏旧采用关系。
- 让四来源错误、取消、出网禁用和真实尺寸可观察并可离线回归。

**Non-Goals:**
- 不扩展 QQ/163 为歌曲元数据、导入、歌词或播放来源，不引入第三方代理服务、Node/Rust sidecar、登录体系或规避访问限制。
- 不按文字为未绑定歌曲自动匹配 MusicBrainz，不跨发行组合并用户封面。
- 不新增图片编辑、裁剪、嵌入音频或图片导出；不自动生成缩略图，也不将小图放大后宣称高清。
- 不顺带完成 G01–G13 全部历史目标；全列表视口优先调度、大曲库虚拟滚动、灰色行身份修复、专辑计数修复及超过 200 首的清单补全不在范围。涉及封面的请求取消、复核取图接线及缓存配置生效必须完成。
- 本轮不改代码、主规格或现行说明；仅创建规划。历史 archive 不重写。

## Decisions

### 1. 以歌集作为所有权，以上游发行作为可复用目录身份

沿用 `release.id` 表示目录所有者，`track.release_id` 表示共享关系。发行组只用于既有代表选择与 CAA group fallback，不成为新的封面共享所有者。无歌集曲目仍可浏览，但更新菜单禁用并解释原因。

增加独立封面存储模型（字段命名可按现有 Go 风格落地）：

- `cover_catalog`：`source`、对象类型及 `source_ref` 唯一，`state=unqueried|found|empty|error`、`checked_at`、`last_error`、短期失败重试时间及目录版本。成功目录/空结果不设自动日期过期；错误可以重试，不代表永久无图。
- `cover_image`：关联目录、上游 `image_id`（CAA 真实 ID；其他来源使用专辑封面身份；本地使用内容指纹）、完整 `types`、主类型、front/back 标记、原始 URL 和元信息。不能仅以发行 ID 聚合所有图片。
- `cover_variant`：图片身份、上游档位（250/500/1200/original 等）、URL、枚举/构造标记、实际宽高（可空）、验证状态、文件格式；HTTP 404 的某个规格只使该规格不可用，不把整个目录记为 empty。
- `cover_file`：规格、所有者（歌集或候选临时身份）、相对路径、内容哈希、字节数、实际宽高、获取/使用时间及是否受采用保护。文件可被临时缓存清理而规格记录仍在。
- `release_cover_selection`：每个歌集至多一个显式采用的图片身份、采用规格及递增 revision。无显式选择时按自动规则选择。不能使用曲目 match_source 代替图片 source。

库内歌集使用 `albums/release-<id>/`；未收藏搜索/复核候选使用 `cache/sources/<source>-<stable-ref-hash>/` 暂存，绝不为了封面创建 release/track。手动搜索中未采用的预览也只存临时区，不纳入目标歌集的本地自动选图集合，避免浏览结果就改变封面。候选入库后将相同来源目录复用并把需要保留的文件原子复制到歌集目录；已入库候选可按来源身份关联本地歌集。

**取舍**：拒绝单一 `hasFetchedCAA` 字段（无法区分无图、故障和不同规格），拒绝把所有信息塞进文件名（不能可靠查询/迁移），也不扩大成通用媒体资产平台。

### 2. 文件名可读，身份与实际像素可靠

文件格式：`<Type>-<source>-<spec>[-<stable-image-suffix>].<ext>`。

```text
covers/
  albums/release-42/
    Front-caa-250.jpg
    Front-caa-1200.jpg
    Back-caa-original-1800x1600.png
    Front-qq-800.jpg
    Front-local-1400.jpg
    Front-qq-800-a3e941.jpg       # 同来源同规格的另一张图
  cache/sources/caa-<ref-hash>/
    Medium-caa-250.jpg
```

- 来源固定为 `caa|itunes|qq|163|local|unknown`，CAA 不标成 musicbrainz；主类型取 Front 优先，其余保留真实 CAA 类型，本地及仅有专辑正面图的来源默认为 Front。
- 数字文件规格以解码后实际长边/宽高为准：方图为 `800`，非方图为 `800x600`，原图为 `original-<w>x<h>`。上游请求档位另存，例如请求 1200 实得 600，文件记 600，记录仍知道请求的是 1200。
- 目录用不可变 ID，不含用户标题；类型、来源、扩展名由受控字段产生，碰撞用图片身份短哈希稳定区分。内容哈希用于校验和同目录去重，不再独占文件名。
- 标准解码器验证 JPEG/PNG，WebP 使用 Go 兼容解码器（优先 `golang.org/x/image/webp`，若尚未依赖则加入与当前 Go 兼容的版本）。以真实内容确定 MIME/扩展名，不信任文件后缀。
- 延续当前 32 MiB 传输边界，但读取 limit+1 后明确拒绝超限，不能截断后当成功。增加解码像素上限（设计默认 64 MP）及尺寸整数溢出检查；不接受 SVG/HTML/动画图为此期封面格式。

**取舍**：不自动重采样以免偏离用户确认的 250 下载规则；因此只有大号本地采用图片时，列表也会显示该图，属于保留手动选择的明确取舍。

### 3. 用途解析器及用户选择优先级

引入 `CoverUsage=thumbnail|detail`，后端返回/服务一个 `CoverTarget`（库内 releaseId 或可信候选身份）。现有 `size` 只描述意图的做法不能继续决定所有缓存键；解析结果缓存键包含所有者、用途、选择 revision、目录版本，图片字节键使用图片身份＋规格。

```text
解析目标 → 读取显式采用关系
  有采用：只在该图片已下载规格中选择 → 有文件则显示；文件全失联则故障
  无采用：检查歌集本地图片
    thumbnail: 取 <600 中最小；detail: 取 >800 中最大
    命中 → 返回本地图片
    未命中 → 是否已有 MB release 身份？
      否 → 本地最小/最大；没有则 nil
      是 → 复用 CAA 目录或获取未查目录
        found → 根据用途下载需要的档位 → 返回实际图片
        empty → 本地最小/最大；没有则 nil
        error → 本地兜底＋错误状态；无本地则失败
```

CAA 自动选图按现有语义：主 Front 优先，其次其他 Front，再按索引顺序其他类型，身份作稳定 tie-break。选定图片的目标档位依次为 thumbnail `250→500→1200→original`，detail `1200→original`；仅尝试目录声明的 URL。同图适用档位均确认不可用后再试下一张图，不进行同次无限循环。若原始发行目录确认无图，再读取已绑定的 release-group 目录；group 返回的实际 release URL 存入目录，不能假装图片来自原发行。

一个下载成功但未达阈值的原图作为兜底返回并标实尺寸，不在同次解析内反复下载/查询；之后凭目录和文件记忆直接兜底。所有候选 URL 已确认不可用时记录规格失败，只有目录有效空或目录请求明确 404 才记 catalog.empty。

本方案将“手动采用优先”作为既有兼容行为保留：手动选的 800 图不被旧 CAA 1200 替代。阈值用于自动图片与采用图片已有规格的选择，不作为强制换图理由。若以后需要为手动采用图下载更多规格，由显式搜索/采用完成。

**取舍**：拒绝“只把详情参数改成 1200”补丁，因为它不能处理已查询目录、本地文件、无图记忆或手动选择。像素统一采用长边，600/800 均为严格边界，不把 CSS 显示大小当图片规格。

### 4. 目录状态与并发调度

自动/手动 CAA 目录入口共用新目录服务与解析器；复用旧 provider 的搜索召回，不继续保留两个独立 CAA HTTP 管线。手动 CAA 搜索先处理目标 MB 发行并按需搜索其他发行，最多检查 10 个去重发行。

- 成功 `found/empty` 持久化，重启不丢；主动搜索或重试使用 force 刷新目标目录及相应搜索响应，成功后替换，失败保留旧有效快照并记录本次错误。
- 失败使用现有有限重试思想及短期退避，不让每一行重复冲击上游；中止请求不记 empty。绑定身份改变自然得到新的目录键。
- singleflight 拆成目录键与图片规格键。thumbnail/detail 同时请求共享目录，但图片传输分别为 250/1200。同图多行共享一个下载。
- CAA HTTP、远程预览、采用和自动图片均经过共享封面并发控制；元数据搜索单独走原有来源令牌桶。目录获取释放并发槽位后再调度图片，不持有槽位等待另一个嵌套任务，避免并发 1 时死锁。
- 替换 `Pool.SetConcurrency` 直接换 channel 的方式为可调整且统计现有任务的控制器：调小后等待运行任务结束，不启动超额任务；所有服务装配与设置更新共用该控制器。
- 每个搜索/预取消费者持有可取消租约；仅某消费者退出不取消仍被其他页面等待的同键请求，无消费者后才中止。关闭搜索弹窗主动取消所属会话，应用关闭取消全部。无需引入完整视口调度系统。
- CAA 及所有图片真正发请求前执行出网 gate；先读本地，不让 `CheckOutbound` 禁用离线读取和本地导入。搜索页统一显示原因及设置入口。

**取舍**：不以进程内 outcomes 代替持久化目录；outcomes 仍可作为展示状态的短期缓存，但按 target/usage/revision 查询，不推断无图。

### 5. 四个封面适配器，保留元数据注册表边界

增加 `internal/covers/sources/` 专用接口，描述来源身份、支持的查询字段/地区、搜索结果、图片身份、有限档位及来源错误。CAA/iTunes 通过适配器复用现有 provider/client；QQ/163 不注册到 `provider.Registry`，不实现与封面无关的曲目补全。前端读取专用来源列表。

| 来源 | 检索/图片策略 | 规格可信度 |
| --- | --- | --- |
| CAA | 目标发行索引＋现有 MB 搜索召回发行，再取 CAA 索引 | 读取 id/types/image/thumbnails；250/500/1200 及 small/large 别名去重，缺档不构造 |
| iTunes | 复用 search、地区解析与共享每分钟 20 次配额，从 artwork URL 形成现有 3000/1200/600/100 有限档位 | 构造档位标待验证，实际图片解码后才能声称尺寸 |
| QQ | 后端直连 QQ 公开 Web 搜索接口的 JSON 查询，按歌曲/专辑结果的 album MID/PMID 聚合专辑图片 | 有返回 URL 优先使用；基于 album 图片身份的有限 300/500/800 构造候选须标待验证并验证 |
| 163 | 后端直连网易云公开搜索（专辑 type=10 或歌曲关联专辑），取专辑 ID、名称及 picUrl；不扩展到音频端点 | 原始 picUrl 与有限缩放候选（如 250/500）分别标记；查询参数不是实际尺寸证明 |

公开参考已做只读检查：
- [CAA 官方 API](https://musicbrainz.org/doc/Cover_Art_Archive/API)：确认图片 ID、原图、250/500/1200、small/large 旧别名、索引顺序和发行组实际来源。
- [qq-music-api-js](https://github.com/huaxianhu/qq-music-api-js)：提供公开 Web 接口及 album MID 封面构造线索；不是官方稳定 API 保证。
- [ncm-api-rs 的 search 实现](https://github.com/SPlayer-Dev/ncm-api-rs/blob/main/src/api/search.rs)：包含 `/api/search/get` 与关键词/type/limit/offset 的请求形状；只作接口线索，不复用其代理、IP 伪装、登录或其他无关能力。

未在本轮声称 QQ/163 真实网络端点已验通。实施先用少量公开、无鉴权的封面查询验证请求方法、响应字段、有效图片和失败码，固定离线 fixture，再接 UI。此处需验证的是两个具体适配器，不是泛化的“探索代码库”。默认保守限制 QQ/163 各 1 请求/秒，遵守 Retry-After。若公开途径实际要求登录、签名绕过或代理，停止该来源实现并报告阻塞，不用恒空占位适配器宣称已支持，也不默默扩大依赖范围。

跨来源查询按 `searchId+targetReleaseId+generation` 管理。启动绑定返回 searchId，各来源完成即发送结果事件；取消绑定终止会话。统一状态结构包含 status/results/error/next-page（若接口支持）；每次有界结果，首次默认最多每来源 20 项，加载更多必须显式触发。不把整批结果等齐后才显示，不吞掉单源错误。

**取舍**：不把社区全量音乐 API 服务打包进桌面应用；只实现需要的查询与图片适配，减少依赖和维护面。具体 QQ/163 请求字段可在验证后微调，不改变以上架构、功能或验收。

### 6. 采用与本地导入是一条提交管线

候选/规格使用服务端生成的 ID，客户端传入 ID 而不是任意远程 URL。采用动作固定 `releaseId` 和预期 selection revision：

1. 验证歌集、搜索会话和图片身份；通过统一下载器取得首选规格，404 时仅退到同图备用规格，传输错误不伪装无图。
2. 校验图片，写同目录临时文件、校验哈希后 rename 到目标文件名。
3. 事务写图片/文件记录和选择关系，检查目标仍存在且 revision 未被另一个采用操作改变；失败保留旧选择，新孤立文件可后续回收。
4. 提交后触发带 releaseId/revision 的封面变更事件及现有 library:changed；前端重新读取依赖的列表、抽屉和专辑详情，不清空当前筛选。

系统文件选择器借鉴 `bindings_import.go` 的 Wails `OpenFileDialog`，提供单个“选择并导入封面”绑定封装固定目标，不复用表格导入的网络 gate。取消返回 cancelled，无错误；路径仅后端持有，不经 AssetServer 暴露任意文件。选取成功即表示采用意图，源文件只读、复制后提交，不移动或修改原文件。

AssetServer 使用受控文件 ID 或目标参数查询路径，只读取已登记的缓存根目录内文件；检查规范化路径、符号链接及越界，网络 URL 限 HTTPS 和适配器认可的域名/重定向，拒绝任意本地/私有网络跳转。旧 adopted-path 入口仅作为已登记历史文件的迁移兼容，不继续允许任意路径读取。

**取舍**：数据库与文件系统不能形成一个事务，因此用“先完成文件、后提交引用、失败保留旧引用”的可恢复方案，不先清除旧图再下载。

### 7. 搜索弹窗布局和前端数据契约

新建 `frontend/src/views/CoverSearchView.vue` 及 Pinia 搜索会话。它使用居中的应用内大弹窗承载，不创建独立系统窗口，不含侧栏，不替换或隐藏现有主内容区和详情抽屉；由 `App.vue` 挂载 Volt Dialog，背景保留原视图、滚动/筛选和详情曲目且不可交互；关闭按钮、取消或 Escape 关闭弹窗并取消所属会话，焦点回到原封面入口。详情右键菜单复用 Volt ContextMenu，焦点区域支持 Shift+F10/菜单键，大图预览叠加在搜索弹窗上层，按 Escape 每次只关闭最上层菜单、预览或搜索弹窗。


卡片默认 object-contain 保留整图，方形容器不裁掉图片内容；来源和规格徽标置于左下角，使用主题可读的高对比度样式和文字，不只靠颜色区分。选择卡片后可用 Volt Dialog 查看大预览，同图规格收拢；小预览只下载一档，不预先拉所有原图。未验证数字显示“800px·待验证”，解码后更新为实际 `800×800`。CAA 的 250 是枚举档位，不等同于必为正方形。

### 8. iTunes 期限删除及文档清理

- 移除 `DefaultTTLDays`、`Config.TTLDays`、`Provider.TTL()` 及“条款要求 TTL”的实现/注释；iTunes search/lookup 写 `TTL=0`，不是回退为通用 30 天。
- 删除 `ITunesTracklistTTLd` 和旧默认值。现有 JSON 解码允许未知字段时直接兼容读取，保存不再输出；测试覆盖旧配置。`stale.go` 的日期判定删除，业务直接读取清单状态，nil release 仍为 none。
- 编号迁移把已有 `provider_cache.provider='itunes'` 行的 `ttl_seconds` 设 0；不动获取时间、正文、收藏字段、来源或用户锁。保留通用缓存和 MusicBrainz 响应 TTL，以及所有来源共用的临时图片容量/TTL。
- 给详情/搜索内部请求选项增加显式 `SkipCache` 传递，`FetchTracklist(force=true)` 的 MB/iTunes 实际 HTTP 请求必须穿透；新手动封面搜索/来源重试同样能取新结果，不能因永不过期缓存失去刷新能力。
- 更新关于页，保留署名、图片不随导出及来源链接，增加 QQ/网易云署名。移除现行 docs 的 iTunes 日期限制，不替换成“本地用途必然合规”的断言。

**取舍**：不删除整个缓存系统、不清空用户数据、不为 iTunes 新增全局后台清理；这是一项本地产品存储策略选择，而非外部法律判断。

## Risks / Trade-offs

- [QQ/163 公开接口不稳定或地域受限] → 来源独立错误/重试，先验证公开最小链路与离线 fixture；真实环境不可用必须在验收报告列为阻塞，不能仅靠 stub 宣布四来源支持完成。
- [永久保存 CAA 空结果导致上游新图不可自动发现] → 符合“不重复自动获取”约束；显式网络搜索刷新目标目录，绑定变化产生新身份。
- [手动大图在列表仍占较多传输/解码资源] → 保留选择而非切换图片；此次不引入生成缩略图，记录为可选后续优化，不改变本次验收。
- [原图过大/畸形/伪装图片] → 32 MiB、像素边界、标准解码、域名/路径限制，失败保留旧图；明确提示而非假成功。
- [文件迁移中断、磁盘不足或目录权限错误] → 复制校验后切换引用、幂等迁移清单、启动可恢复、不删旧文件；禁止静默重建空缓存使旧封面失联。
- [同发行多图混淆和构造档位虚报] → 图片 ID 与规格独立建模，同图退档，实际解码记录，离线非方图和重复类型样例。
- [前后端异步更新串台] → searchId/target/revision 守卫，固定采用目标，全部依赖界面订阅同一封面变更事件，浏览器与真实绑定双层测试。
- [数据库扩大且历史记录来源不全] → 只迁移可证明的信息，未知明确标 unknown；可重取旧 tmp 不保证保留，用户 adopted 必须保留。
- [文档清理被误读为第三方条款确认] → 删除未经核验的保存期限强制主张，同时保持中性的来源/版权说明；不作合规背书。

## Migration Plan

1. 进入 apply 后先保存现有数据库及已采用目录的备份；新增编号迁移，不修改既有 migration0001。迁移创建封面表、选择/迁移记录并转换 iTunes 缓存 TTL，支持已建数据库和全新数据库。
2. 根据每条 `release.cover_path` 建待迁移记录，读取原文件验证后复制至 `albums/release-<id>/`，记录真实尺寸/可确认来源/采用状态。同一旧哈希文件被多个 release 引用时分别迁移各自所有权。新记录完成前保留旧路径读取。
3. 文件迁移失败不删除原路径，重启继续；旧临时缓存能按已有来源键确定身份时复用，否则允许失效重取，但不能把旧 outcomes 当作永久空目录。
4. 接通新解析器、四来源适配器、采用与本地导入，再迁移前端 DTO/事件/API，生成 Wails 绑定。旧字段仅作迁移兼容，不长期双写成为第二套事实来源。
5. 保存封面根目录变更时暂停新的写任务、等待或取消未完成写入、复制保护文件并校验、更新根目录和服务配置后恢复。失败保持旧设置；临时图可舍弃，CAA 目录与采用身份不能丢失。
6. 完成离线、绑定和前端测试，原生验证文件选择器以及真实 QQ/163 查询；更新现行文档、已知问题和验证记录。只有真实支持和人工验收证据齐备才将对应任务打勾。
7. 回滚不执行破坏性 down migration：旧版本不理解新 schema 时按既有机制拒绝打开，恢复配套数据库/封面备份后使用旧版本。保留升级前文件直到迁移确认完成，回滚后新增采用记录不能由旧代码自动恢复，应在回滚说明中提示。
