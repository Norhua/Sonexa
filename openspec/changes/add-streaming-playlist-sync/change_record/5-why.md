# 5 — 候选专辑名统一显示本地发行状态

## 原始提示词

> 当前修改记录在 change 中的 change_record 目录。
> 前面我们指定了"将'release group 已存在'和'release 已存在'"放在复核队列的来源中，但是这样其实不太合理请你：
> 1. 移除复核队列，来源下的'release group 已存在'和'release 已存在'
> 2. 在 release group 已存在时将专辑名改为橙色，当 release 已存在时将专辑名改为绿色
> 3. 我测试中还发现不仅复核队列需要这个效果，搜索上游的结果也需要这个效果，所以至少修改这两处，你可以检查一下还有没有其他地方也可以使用这个效果一起修改

## 追问、选项及选择

- 本轮没有追问或选项选择。
- 两个状态同时为真时采用更具体的发行状态：绿色优先于橙色；均不存在则保留原文字颜色。已在执行前向用户说明。
- 检查发现编辑弹窗的上游候选列表也适用，按用户授权一并修改；普通曲库/同步曲目列表不着色，避免把本地发行存在性与音乐库归属混淆。

## 修改目的与边界

- 复核来源列只保留上游和精确本地曲目徽章，移除修改 3 引入的两种发行文字徽章。
- 复核、上游搜索和编辑搜索候选共用专辑名展示逻辑；绿色表示具体 release 已存在，橙色表示仅原生 release group 已存在，保留完整专辑名、类型提示以及可访问的状态说明，适配明暗主题。
- 存在性继续由后端按同来源精确身份查询，包含同步专属数据。不以专辑同名、所属组或 recording 推断，不改变匹配、自动选版、准入、接受/跳过等行为。
- 搜索和复核已有实时投影；编辑搜索当前仅调用 rowFrom、没有本地状态，需要补充同一批量投影。编辑中的本地变化只刷新候选展示，不改草稿、选中候选或上游预览；本地曲目标记区分已入库和仅本地存在。
- 原 change 的 proposal/design/specs/tasks 保留不动；本轮任务、验证和最终差异分别写入 `5-tasks.md`、共享 `spec-diff.md`。原 55/59 的平台及在线验收不属于本次。
- 本轮开始时工作区干净；不清空或修改用户应用数据，不调用真实上游，不委派子代理。
