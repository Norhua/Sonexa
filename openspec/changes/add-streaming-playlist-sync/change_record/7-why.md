# 7 — 复核队列布局、全量候选与浏览位置保留

## 原始提示词

> 当前修改需要记录到 change 中的 change_record 中
>
> 如图 ./tmp/image/image31.png，做以下修改
> 1. 将复核队列页面上面的条目信息展示移动到下面
> 2. 将条目信息中的下一条/上一条按钮移动到右下角
> 3. 只显示返回了多少条，清除两个按钮及相关逻辑代码，直接显示所有返回结果
> 4. 重新进入复核队列页面是不要重置到第一个，而是保持上一次到达的位置

## 追问、选项及选择

本轮没有追问或选项选择。截图明确标出了“显示全部”“无一匹配”两个待删除按钮，不是搜索区的“无需匹配”。

## 修改目的与边界

- 将当前条目的标题、原因、原始输入、证据和失败说明放到候选列表下方；逐条导航固定在该区域右下角。候选区域独立滚动，长证据区域可滚动，导航保持可见。
- 删除候选的前十条截断、展开按钮与展开草稿；直接展示所有返回结果，复核页结果底栏只显示“返回 N 条”（含 0 条）。搜索页原本已全量展示，保持该入口布局不变。
- 删除“无一匹配”按钮、专用后端方法及 Wails 绑定；保留“无需匹配”、移出、接受/跳过、失败重试及通用候选/身份清理逻辑。
- 将复核浏览游标放入 Pinia，在同一应用会话内离开页面后重进恢复条目 ID；队列变化优先保留同一条目，消失时使用原索引并校正到有效范围，空队列清空游标。重新进入仍读取最新队列，不缓存旧快照、不自动重搜、不要求跨应用重启保存。
- 保留已有搜索草稿切换语义、旧响应失效、后台事件刷新、候选封面与准入规则；不改数据库或上游差异处理。
