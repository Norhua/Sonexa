# Spec Delta

## Purpose

保证 Spotify 歌单读取所需的独立辅助运行环境随 Sonexa 一起交付，在用户未安装开发工具的桌面环境中可用。约束进程启动、资源边界、网络控制和升级验证，避免第三方运行环境绕过应用的生命周期与安全规则。

## ADDED Requirements

### Requirement: 随应用交付且无运行时安装
每个声明支持 Spotify 的发行包 SHALL 包含与目标系统及架构匹配的辅助程序、运行环境和全部依赖。首次使用不依赖系统 Python、pip、uv、用户环境变量或在线安装；运行环境与应用按版本整体交付，附依赖版本、完整性信息和许可证。

#### Scenario: 干净系统
- **WHEN** 用户在没有 Python 和包管理器的受支持系统安装 Sonexa
- **THEN** 可启动随附辅助程序完成离线自检，并在满足网络条件时读取公开歌单，不弹终端或安装依赖

#### Scenario: 缺失或损坏
- **WHEN** 辅助程序缺失、架构不符、版本不兼容或完整性检查失败
- **THEN** 明确提示 Spotify 运行环境不可用并拒绝调用，不回退到 PATH 中的可执行文件、不静默下载修复；QQ 与本地浏览继续可用

### Requirement: 受控通信与执行
辅助进程 SHALL 仅从应用认可的安装位置启动，使用有版本和请求标识的受控通信协议；歌单地址、名称和其他外部内容只作为数据，不拼接到命令、脚本或文件路径。通信限制消息大小、总输出、超时和并发；日志不得泄露匿名访问令牌或完整响应。

#### Scenario: 异常输出
- **WHEN** 辅助进程返回损坏消息、错误请求标识、超限数据或异常退出
- **THEN** 本次读取失败且旧快照保留，不接受部分输出，不阻塞应用其他能力

#### Scenario: 路径与外部输入
- **WHEN** 安装路径含空格/中文，或歌单输入含命令分隔符
- **THEN** 合法安装路径仍可运行，非法歌单被拒绝，外部输入不能形成命令执行或任意文件访问

### Requirement: 辅助请求遵守应用网络策略
辅助进程触发的所有实际网络请求 SHALL 受应用当前网络门禁、平台配额、允许目标、请求预算和取消约束，包含匿名会话、分页、详情、重试和重定向。关闭出网后不得继续发起后续请求；不通过用户 Cookie、浏览器凭据、任意代理或自动升级第三方代码绕过约束。

#### Scenario: 运行中禁网
- **WHEN** 分页进行中应用关闭出网
- **THEN** 后续请求被拒绝，当前操作结束且不提交快照，重新启用须由用户再次发起

#### Scenario: 内部重试
- **WHEN** 第三方读取层请求重试或重定向
- **THEN** 每次实际发送均计入同一平台预算并检查允许目标，不能在辅助进程内另开不受控直连路径

### Requirement: 生命周期与恢复
取消、超时、删除绑定或应用退出 SHALL 终止相关辅助任务并回收进程、通信句柄和临时资源。重启后使用持久化的最后成功状态及导入队列，不续用未确认的抓取输出；用户可显式重试失败读取。

#### Scenario: 退出或强制中断
- **WHEN** 辅助程序无响应或应用退出
- **THEN** 在有限等待后终止相关进程，不留下后台常驻抓取，不写入半份歌单
