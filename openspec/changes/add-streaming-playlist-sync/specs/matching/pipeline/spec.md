# Spec Delta

## MODIFIED Requirements

### Requirement: 导入处理与状态
导入 SHALL 先按[已入库输入证据](../provenance/spec.md#requirement-已入库输入证据)离线检查整个 track 表中的所有来源及无绑定本地曲目，不按 in_library 过滤；确认重复则直接 skipped，不先创建复核条目、不隐式改变入库状态，但须完成相应同步目标关联。不能确认时再以 MusicBrainz 查询、评分并分流，检索后用同一证据规则复查。条目状态为 queued、matching、imported、review、failed、skipped、merged、discarded；imported 表示完成导入而不必然入库。不再通过 ISRC 或无绑定文本命中构造疑似本地候选。

#### Scenario: 本地已存在
- **WHEN** 原始输入能唯一确认某条 QQ、MusicBrainz 或无绑定本地曲目，不论是否入库
- **THEN** 不请求默认上游、不新建曲目，直接 skipped 并记录已有曲目和输入确认关系；不切换主来源、不改变 in_library，同步目标关联该曲目并完成导入

#### Scenario: 证据不足
- **WHEN** 仅有同 recording/ISRC、多个等强目标或无法证明相同 track 的相似文本
- **THEN** 不直接跳过，继续检索和分流；无法自动判定时保留复核

#### Scenario: 表格重复命中未入库曲目
- **WHEN** 表格导入可靠命中仅存在于同步歌单的 track
- **THEN** 同样 skipped，不因导入目标写着音乐库而自动改变 in_library，用户须显式入库

### Requirement: 活动输入合并
系统 SHALL 在事务中分离每次有效输入、活动主条目、导入目标和最终曲目。对能唯一确认的相同活动目标，只保留一个 queued、matching、review 或 failed 主条目；被吸收输入为 merged，并以 merged_item_id 指向主条目，不将旧 merged_into 收藏目标字段当作条目关联。每个输入保留自身目标，主条目成功时向所有仍有效目标投递同一曲目。主条目接受、跳过或丢弃后，被吸收输入仍为终态，不重新排队。

#### Scenario: 主条目结束
- **WHEN** 主条目被接受、跳过或丢弃
- **THEN** 被吸收输入继续保留 merged 终态及原批次关联，不重新排队；成功结果向仍有效同步目标关联，丢弃按目标记为忽略或普通移出

#### Scenario: 多目标合并
- **WHEN** 两个同步歌单和一次文件输入按既有严格证据合并到同一主条目
- **THEN** 只执行一次匹配，页面列出全部目标；若新建曲目且音乐库目标仍有效则入库，仅有同步目标则不入库；若结果为已有 track 的重复跳过则不改变入库状态

#### Scenario: 合并后撤销一个目标
- **WHEN** 某同步歌单删除或上游移除其中尚未导入的条目
- **THEN** 只撤销该需求，其他有效输入及目标继续处理；即使撤销的是最初主输入也不丢失其他需求，不允许旧计划向已撤销目标写入

### Requirement: 已有复核离线整理
读取复核队列或任务汇总前，系统 SHALL 在事务内按原始输入、整个 track 表的当前事实、有效确认关系及已有候选证据整理未手动改搜的 review/failed 条目，唯一确认重复时 skipped 并完成有效同步目标关联；不按 in_library 过滤、不隐式入库、不触发网络、不重做终态。手动搜索开始即标记手工会话，读取整理不能处置在途或已改搜条目，也不能把手动搜索本身当作接受/跳过。

#### Scenario: 后台新增收藏
- **WHEN** 某未改搜复核条目的目标被其他入口保存为已入库或同步专属曲目
- **THEN** 再读队列或汇总时离线排除已能唯一确认的重复，复核页监听本地曲目与目标变更并刷新；证据不足或已手动改搜的条目保留

### Requirement: 进度与日志
后端 SHALL 推送进度并记录可辨认输入、导入目标和分流原因。完成统计互斥区分新建曲目完成导入、复核、未匹配、失败、跳过、合并输入和移出；入库归属不冒充导入统计。新增发行、归组资料不足和冲突均纳入复核并记录具体原因。分母为各批次实际有效输入数，merged 和 skipped 均计已处理，撤销需求按移出记录而不减少历史分母，暂停时待处理不作终态。

#### Scenario: 完成统计
- **WHEN** 全部有效输入处理完成且尚未人工处置
- **THEN** 七类之和等于有效输入数，新增发行条目计入复核，日志区分无匹配与请求错误；被吸收输入仍在其原批次统计，不声称原四类覆盖全部输入

#### Scenario: 运行状态变化但处理数不变
- **WHEN** 导入开始、完成、暂停、失败重排或切换批次，即使已处理数量没有变化
- **THEN** 推送完整任务状态并刷新队列；最终通知发出前已退出运行集合并保存终态，读取不再返回已结束任务仍运行

#### Scenario: 逐首成功提交通知
- **WHEN** 导入曲目、重复目标关联或一首详情补全已成功提交
- **THEN** 立即通知对应曲目、同步歌单与队列视图刷新，不等待后续可选网络补全或整轮任务退出；失败或取消不伪报成功变更

## ADDED Requirements

### Requirement: 同步需求撤销与重新导入
同步目标全部失效时，系统 SHALL 取消对应活动工作，后续回调不得新建无归属曲目、复活条目或写入被删除目标。用户恢复忽略项须建立新的有效导入尝试，保留旧终态，不把历史 discarded 或 merged 改回活动状态。仍有效目标的原始输入和人工搜索草稿须保留。

#### Scenario: 匹配期间删除绑定
- **WHEN** 唯一同步目标在匹配请求尚未返回时被删除
- **THEN** 停止相关工作，迟到接受、重试或失败均无权保存结果；重启后不恢复该目标

#### Scenario: 部分恢复忽略
- **WHEN** 原主条目同时服务 A/B，移出后用户仅恢复 A 的忽略项
- **THEN** 新尝试只携带 A，B 保持忽略，不因原合并关系而恢复 B
