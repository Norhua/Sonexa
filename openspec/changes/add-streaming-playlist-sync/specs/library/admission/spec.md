# Spec Delta

## MODIFIED Requirements

### Requirement: 预览与提交分离
准入 SHALL 先产生包含确定候选、组证据、成员动作、实体修订和有效导入目标的保存计划，再按计划提交。搜索、详情预览、编辑使用及确认弹窗本身不创建正式曲目或成员。基本字段缺失不构成存储失败；无法判组时按发行组规格保存未知状态。仅用户明确选择的候选参与交互入库，不自动更换版本。导入目标由持久化输入解析，不允许前端把同步需求改为音乐库需求；同步保存仍遵守相同发行成员准入。

#### Scenario: 搜索选定版本
- **WHEN** 用户明确选择一个曲数较少的版本并请求加入
- **THEN** 为该具体版本准备计划，不以自动选版规则替换它

#### Scenario: 取消确认
- **WHEN** 用户取消新增发行或影响预览确认
- **THEN** 曲目、发行、归组、队列终态和同步目标关联不变；编辑草稿或复核候选保持可继续处理

### Requirement: 原子结果与重复请求
一次提交 SHALL 原子保存曲目、发行、组映射、当前字段、快照、来源状态、艺术家关系、索引、对应导入/复核终态和有效目标关联，以及包含全部被吸收输入的确认关系和接受时目标上下文。交互明确加入精确来源曲目身份重复时返回已有曲目，不创建第二条；自动导入仍须通过输入核验，重复跳过不改变 in_library。新曲目按有效目标决定是否入库。重复提交成功计划返回同一结果。任何校验、数据库或文件准备失败均不得留下部分关系、确认或错误终态。确认复用以[接受时目标基线](../../matching/provenance/spec.md#requirement-已确认输入关系复用)核验，不重新否定用户已明确批准的版本差异，也不改变自动选版规则。

#### Scenario: 接受保存失败
- **WHEN** 复核接受已获确认但提交前文件准备或事务写入失败
- **THEN** 条目仍可处理，旧曲目数据和文件引用保持有效，不显示已接受；没有部分同步目标提前成为已导入

#### Scenario: 两个入口加入同一身份
- **WHEN** 搜索和复核并发加入同一来源同一曲目标识
- **THEN** 最终只有一条曲目，两入口均可得到已有身份；搜索明确入库生效，同步复用不会取消入库状态

## ADDED Requirements

### Requirement: 导入目标并发重验
准入提交 SHALL 在写事务内重验当前主条目、全部有效输入、目标修订、同步绑定存在性以及条目仍在上游且未忽略。目标撤销、忽略或新增合并需求后旧计划失效；无有效目标时不创建孤立曲目。不因精确身份已存在而跳过目标有效性核验。

#### Scenario: 接受前删除歌单
- **WHEN** 用户预览接受后删除目标同步歌单，再提交旧计划
- **THEN** 拒绝提交，不创建曲目或恢复歌单，其他有效任务保持可处理

#### Scenario: 已有身份也须验证
- **WHEN** 旧计划命中已有 track，但相应同步需求已被忽略或上游移除
- **THEN** 不向失效目标投递结果，不把目标恢复成已导入
