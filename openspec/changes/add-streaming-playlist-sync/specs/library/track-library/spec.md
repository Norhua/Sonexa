# Spec Delta

## MODIFIED Requirements

### Requirement: 缺失值与删除
未知字段 SHALL 使用缺失值，界面显示占位，导出保持为空。基本字段不作必填校验；空值不参与名称归组、文本重复判定或合并。精确身份重复仍返回已有曲目。从音乐库删除时，清理普通歌单和标签归属；仍被任一同步歌单引用则仅取消入库，保留曲目、字段、艺术家关系及同步关联，否则物理删除并清理附属数据。发行仍有本地曲目引用则保留，无曲目引用发行按[存储清理规则](../../platform/data-store/spec.md)删除，不能仅因无已入库曲目而删除同步数据。

#### Scenario: 删除后清单仍可浏览
- **WHEN** 删除已收藏清单位置，但该发行仍有其他已入库曲目
- **THEN** 该位置在音乐库专辑中回到灰色行，其他收藏与清单不变；若被同步歌单引用，其本地记录继续保留

#### Scenario: 两首未知曲名
- **WHEN** 用户明确创建两首无上游身份且曲名、署名均缺失的曲目
- **THEN** 分别保存两条本地收藏，不因空文本相同合并

#### Scenario: 从音乐库移除同步共享曲目
- **WHEN** 一首曲目同时在音乐库、普通歌单和同步歌单中，用户从音乐库删除
- **THEN** 取消入库并清理普通集合归属，同步歌单继续显示该已导入曲目但不再显示已入库标记；不重新进入导入队列

## ADDED Requirements

### Requirement: 导入与曲库成员分离
曲目 SHALL 独立保存 in_library 与入库时间。完成同步导入的新曲目默认 in_library=false；queued、review 等任务不是已导入曲目。音乐库列表、最近添加、艺术家、专辑、资料库搜索和全库导出只使用 in_library=true，内部身份查询和导入判重仍覆盖全部曲目。普通本地创建、搜索明确加入及非重复文件导入保持入库行为。

#### Scenario: 同步不污染音乐库
- **WHEN** 用户完成同步歌单的自动匹配或无需匹配保存，但没有主动入库
- **THEN** 本地 track 存在且同步页面可见，音乐库各视图、计数、空库判断和导出仍不包含它

### Requirement: 显式入库为幂等归属操作
已导入本地曲目 SHALL 可显式加入音乐库，按本地曲目身份去重，在事务中重新检查存在性与入库状态；只设置曲库归属，不复制曲目、重新匹配、改变元数据绑定或重置字段。已入库项报告已经存在，不重复更新入库时间；取消预览不改变任何归属。

#### Scenario: 混合批量提交
- **WHEN** 批量入库预览后某曲目已由其他操作入库
- **THEN** 提交按当前状态报告已存在，不重复添加；若曲目被物理删除则提示重新预览，不产生部分批量结果

### Requirement: 入库时间不等于导入时间
系统 SHALL 分开记录曲目创建时间与首次入库时间。未入库且从未入库的曲目没有入库时间；首次显式入库时设置，字段编辑、重复跳过和同步不改变它。曲目保留而暂时取消入库时保留历史首次入库时间，再次加入不重置；最近添加仅包含当前已入库曲目并按该时间排序。

#### Scenario: 延后入库
- **WHEN** 歌曲先导入同步歌单，一周后首次加入音乐库
- **THEN** 最近添加和加入时间使用一周后的首次入库时间，不使用抓取或导入完成时间

#### Scenario: 取消后再入库
- **WHEN** 同步引用保留的歌曲从音乐库移除后再次入库
- **THEN** 恢复同一 track 的入库标记，首次入库时间不变
