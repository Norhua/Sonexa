# Spec Delta

## MODIFIED Requirements

### Requirement: 统一集合模型
普通歌单与标签 SHALL 使用同一模型和增删改接口，以 kind 区分；同名约束在种类内生效。一首已入库曲目可加入多个普通歌单和标签，同一归属不能重复。同步歌单使用独立只读成员模型，不得通过普通集合接口创建、添加、移除或重排同步成员。

#### Scenario: 名称与归属
- **WHEN** 用户创建同名普通歌单和标签，或重复添加同一已入库曲目
- **THEN** 不同种类可同名，同种类重名被拒绝；重复添加不产生第二条归属

#### Scenario: 同步标识不能当普通集合
- **WHEN** 请求把同步歌单作为普通集合目标
- **THEN** 明确拒绝，不修改同步成员或上游数据

### Requirement: 组织入口
加入普通歌单或标签 SHALL 从我的音乐库中的曲目表格右键菜单发起，支持多选；上游候选、复核候选及同步专属曲目须先入库再组织。服务端须逐项重验 in_library，混入未入库或已删除曲目时拒绝整个添加，不自动入库、不部分写入。同步页面不提供普通集合组织入口，即使某行已经入库。

#### Scenario: 批量添加标签
- **WHEN** 用户多选十首库内曲目并添加标签
- **THEN** 十首获得该标签，上游候选和同步歌单表格不提供此操作

#### Scenario: 绕过界面添加
- **WHEN** 直接向普通歌单添加未入库同步曲目，或预览后曲目被移出音乐库
- **THEN** 后端拒绝添加，曲目仍仅在同步歌单，不以存在 track ID 作为入库依据
