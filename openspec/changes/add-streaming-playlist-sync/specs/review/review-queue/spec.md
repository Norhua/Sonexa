# Spec Delta

## MODIFIED Requirements

### Requirement: 处理动作
复核候选行 SHALL 仅提供接受或跳过：未绑定候选显示接受，精确绑定候选显示跳过，不以是否入库判断本地绑定。条目级仍保留无需匹配按原始已知信息保存、移出队列、无一匹配和失败立即重试。接受重新准备统一准入计划，必要摘要在提交前取得，完整详情随后补全；向已有组引入新发行时，点击接受后须额外确认，取消保持待处理。无需匹配允许缺少曲名、艺术家或专辑，若创建发行命中已有组同样执行成员确认。成功结果向所有有效导入目标投递，仅同步目标的新曲目不入库。

跳过 SHALL 调用 SkipReviewCandidate，由服务端重新查来源 + track 标识的当前精确绑定，不信任前端 localTrackId；成功将条目标记 skipped、记录 track_id 并完成有效同步目标关联，不修改曲目字段、入库状态或新增曲目，绑定失效则拒绝。接受、无需匹配、明确跳过在对应事务中保存包含被吸收输入的[确认关系](../../matching/provenance/spec.md#requirement-已确认输入关系复用)；无一匹配清空候选及旧自动解析身份并保留条目，不再提供 MergeCandidate 合并已有收藏动作。移出队列对同步目标记为主动忽略，对音乐库目标维持普通丢弃语义。

#### Scenario: 接受或跳过
- **WHEN** 用户选择未绑定上游候选或精确已绑定候选并完成该动作所需确认
- **THEN** 分别保存候选或记录 skipped 及已有本地身份；处理结果、确认关系和有效目标关联同事务结束，接受不借原始文本补齐候选，跳过不改曲目或入库状态

#### Scenario: 跳过前绑定失效
- **WHEN** 候选显示本地，但点击跳过前曲目已删除或换绑
- **THEN** 后端拒绝跳过，不按前端缓存本地 ID 结束条目；仅 in_library 变化不视为绑定失效

#### Scenario: 无需匹配与无一匹配
- **WHEN** 用户选择无需匹配或无一匹配
- **THEN** 前者在准入后按已知原始信息保存并结束，缺失字段为空，按有效目标决定新曲目是否入库；后者继续留在队列

#### Scenario: 接受后二次确认取消
- **WHEN** 用户点击接受，再取消新增发行确认
- **THEN** 条目、候选、原因、搜索草稿与已有库数据保持原状，不把明确取消当作成功动作刷新

#### Scenario: 成功动作即时刷新
- **WHEN** 移出队列、跳过、无一匹配或立即重试成功，包括接口成功没有业务返回值
- **THEN** 即时刷新条目、位置和全局任务计数，末条移出显示空态，无一匹配清候选但保留条目；同步目标的关联或忽略状态同时刷新，旧响应不恢复已处理状态，失败保留条目和错误

## ADDED Requirements

### Requirement: 复核导入目标提示
复核页面 SHALL 在重新搜索下方的“恢复原始信息”“无需匹配”“移出队列”按钮同一行最右侧展示导入目标；音乐库为“to 音乐库”，同步歌单为橙色“to 歌单显示名”。合并任务列出全部不同有效目标，长名称可省略并查看全文；失效目标及时移除，不以单一目标掩盖共享任务。

#### Scenario: 切换与合并目标
- **WHEN** 从普通文件条目切到同时服务两个同步歌单的条目
- **THEN** 右侧提示改为两个橙色歌单名称，不继承上一条“to 音乐库”，接受会完成两者关联

#### Scenario: 移出共享任务
- **WHEN** 用户对显示多个目标的主条目选择移出队列
- **THEN** 撤销当前显示的全部有效需求，同步目标进入各自忽略列表；随后可在单个歌单的同步确认弹窗单独恢复
