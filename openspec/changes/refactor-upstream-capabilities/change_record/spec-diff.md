## SD-1：歌词占位由来源归一化，不是全局正文黑名单

**关联规格**
- 主规格 `openspec/specs/upstream/lyrics-search/spec.md`：“歌词来源传输与格式边界”“通道状态与合并正文”。
- change delta `specs/upstream/provider-registry/spec.md`：“业务能力调用契约”。

**实现现状**
- `internal/provider/netease/lyrics.go` 解释网易云原文、翻译、罗马音中的“纯音乐，请欣赏”“暂无歌词”等占位；原文占位返回统一 `lyrics.ErrNoLyrics`，附加通道占位归一化为 unavailable，不丢失可用原文。
- `internal/lyrics` 不再识别占位文案，统一校验 UTF-8、大小和文本/LRC 格式并合并通道。内容超限或损坏仍报告解析错误，不能因同时出现占位而隐藏错误。
- 其他来源已交付的合法正文不会仅因包含同样句子而被公共层拒绝。本地文本导入边界不变；若其他上游有自己的占位约定，应在相应适配器补归一化，不恢复公共黑名单。

**差异/冲突与后续同步建议**
- 与主规格明确规定的“网易云占位不是歌词”一致，无反向冲突；旧实现把此规则扩散到所有上游，本轮收窄回来源语义。
- 建议在“业务能力调用契约”补充：来源须在交付业务结果前将原生空内容/占位状态归一化，调用方不得依据某平台文案判断可用性。
- 补场景：网易云原文占位拒绝；网易云只有附加通道占位时原文可采用；另一已登记来源返回相同文字的真实正文时保留。
- 不应在主 spec 中规定新的通用敏感词列表，也不应要求所有来源无条件接受其自己的占位响应。

## SD-2：自动封面回退目标及本地复用身份由策略声明

**关联规格**
- 主规格 `openspec/specs/upstream/cover-art/spec.md`：“自动尝试顺序”。
- 主规格 `openspec/specs/platform/data-store/spec.md`：“未收藏候选的封面数据”。
- 主规格及 change delta `upstream/provider-registry`：“统一封面行为”“业务能力调用契约”。

**实现现状**
- 删除 `provider.ArtworkStrategy.GroupFallback`；`CatalogKeys` 统一声明合法的、有序的主目录及后备目录身份，自动解析和本地预览复用使用同一份身份规则。
- `covers.Resolve` 仅在当前目录确认为 empty 时尝试下一目标；协议错误和取消终止远程目录回退，已 found 目录的图片档位选择不转移到其他目录身份。原有可用本地图片兜底仍保留。
- CAA 适配器声明有效 release → 已绑定有效 release-group；无效主身份不产生目标，无效/缺失 group 不加入回退。iTunes/QQ 仍只声明自身有效专辑目录。
- 未入库候选也能直接读取声明的后备目录已保存预览，不为了复用它再次走目录/网络流程；既有入库复用同样使用 `CatalogKeys`。
- 未增加生产来源、未启用仅有手动封面搜索能力的来源自动取图；图片安全策略、门禁、工作池和来源快照仍生效。

**差异/冲突与后续同步建议**
- 与现有 CAA 回退、本地优先要求一致；改变的是职责边界，未把 CAA 的规则推广为所有来源都必须支持发行组。
- 主 spec 可补充统一行为：自动取图按所登记图片策略提供的有序目录身份回退，调用方不构造来源特有对象类型；只有明确无图推进下一目录，错误不可伪装为空结果。
- 主 spec 保留 CAA/iTunes/QQ 的具体业务规则，不把 Go 字段名写成规范要求。`GroupFallback` 删除和 `CatalogKeys` 扩展归架构说明后续核对项。
- 补场景：非 CAA 策略可声明不同对象类型的多级目标；候选后备预览在禁网时复用；错误/取消不继续后备请求。

## SD-3：地区输入由能力决定，不由 iTunes 名字决定

**关联规格**
- 主规格 `openspec/specs/upstream/cover-search/spec.md`：“网络搜索大弹窗”（当前只写 iTunes 地区选择）。
- 主规格及 change delta `upstream/provider-registry`：来源地区需求、同能力替换和统一业务输入。

**实现现状**
- 页面从与执行共用的登记列表中读取 `needsCountry`；至少一个已选来源声明需要地区时显示控件。
- 控件文案为“封面来源地区”“来源默认地区”，不再使用 iTunes ID 判断。显式国家值按统一 Query 传递，空值继续交由各适配器按默认规则处理，iTunes 已有默认地区规则不变。

**差异/冲突与后续同步建议**
- 主 spec 的 iTunes 描述不再完整表达地区输入的适用范围，但 iTunes 行为本身没有冲突。
- 将“iTunes 地区可选择并沿用现有默认规则”扩展为：按已选来源的地区能力显示地区选择，空值遵循该来源默认规则；保留 iTunes 默认设置的引用。
- 补场景：只登记一个非 iTunes、需要地区的封面来源时，仍显示地区控件并正确传参；取消所有需要地区的来源后隐藏。

## SD-4：来源展示、选择和执行共享登记列表及生命周期

**关联规格**
- 主规格 `openspec/specs/upstream/cover-search/spec.md`：“网络搜索大弹窗”“四来源结果与失败隔离”。
- 主规格 `openspec/specs/upstream/lyrics-search/spec.md`：“双栏搜索与分来源状态”。
- change delta `specs/upstream/provider-registry/spec.md`：“接口与注册表”“业务能力调用契约”。

**实现现状**
- 两个前端 store 在每次打开时加载后端列表并取得目标修订，二者成功且仍是当前打开操作后才 ready；页面不另外加载一份列表。
- 首次成功加载列表时按登记顺序默认选择全部。以后重新打开保留现有选择与新登记列表的交集、去重，不自动勾选新增来源，也不覆盖用户主动取消全部的选择；移除的来源不再发送请求。
- 单来源重试先检查该来源仍在当前打开的登记快照中；无效来源明确报错，不创建歌词会话或启动封面查询。
- 列表未加载、加载失败、关闭后迟到的响应均不能启动搜索或恢复过时来源；成功空列表不回退固定名单。打开中的查询维持该次列表快照，重开时更新登记信息，既有会话取消/迟到结果规则不变。
- 生产默认仍为原四封面/四歌词来源及原顺序，没有新增硬编码默认集合。

**差异/冲突与后续同步建议**
- 这是对 change delta“同一份已登记能力信息”的完整落实；主 spec 的固定内置列表继续描述默认配置，不应作为前端合法来源白名单。
- 主规格尚未明确前端初始选择、重开交集和列表加载失败语义，建议增加以上规则，而非要求每次打开都重置全选。
- 补场景：单能力来源作为唯一登记来源时默认执行只请求它；移除来源后重开不会发隐藏旧请求；列表失败/空集合不使用静态兜底；关闭或切换目标后旧列表响应不覆盖当前状态。

## 冲突与验证边界汇总

- 本轮未发现必须牺牲现有主 spec 功能才能修复的冲突；SD-1 收窄了旧实现不恰当的全局过滤，SD-3/SD-4 补全了现有规格未充分表达的能力驱动和选择生命周期。
