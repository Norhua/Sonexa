## Goals / Non-Goals

**Goals:**

- 上游负责来源语义，用例服务负责计划与业务决策，存储负责一次提交；相同上游数据只经过一种同步规则。
- 分离身份、事实、用户当前值、展示投影，降低编辑、补全、封面和多版本视图互相牵连的程度。
- 将缺失、未知、明确清空与用户覆盖建模为不同状态；异步响应、并发和文件失败都可恢复。

**Non-Goals:**

- 不增加本地音频扫描或写标签、艺术家别名智能合并、跨来源曲目自动去重、编辑历史。
- 导入继续使用 MusicBrainz，出网条件继续沿用联系方式规则；不重新制定 QQ 封面与元数据配额，也不承诺解决 iTunes 超长清单取全问题。
- 不把已有 known gaps 全部纳入此变更；只按实际实现和测试收敛 G01/G02/G03/G06/G08 及涉及的 G11 部分。旧模型移除后重述 G15，不将删迁移等同于通过历史升级验证。

## Decisions

### 1. 用例服务注入来源契约，统一快照

增加 `internal/library` 用例层，注入 registry、store、文件服务和 clock。App 保持 Wails 参数转换、事件与生命周期；组装点可以知道具体来源，“导入只用 MB”作为产品策略保留在组装处。领域 DTO 放无具体来源依赖的公共包，避免 store 与 provider 相互依赖。

建议接口形状：

```go
type Provider interface {
    // 保留 ID、DisplayName、Capabilities、RateLimit、IsConfigured
    Refs() RefCodec
    SearchTracks(context.Context, Query) ([]Candidate, error)
    SnapshotFromCandidate(Candidate) (*Snapshot, error)
    Complete(context.Context, DetailTarget) (*Snapshot, error)
    LoadReleaseSummary(context.Context, ReleaseIdentity) (*ReleaseSummary, error)
}
type VersionLister interface {
    ListVersions(context.Context, GroupIdentity, Page) (VersionPage, error)
}
type ArtworkProvider interface {
    LoadArtworkCatalog(context.Context, ArtworkTarget) (*ArtworkCatalog, error)
}
```

`SnapshotFromCandidate` 明确表示纯转换，不出网、不写库；相较把方法叫 `Admit`，更不容易误把领域准入放进来源实现。摘要接口允许返回不支持/未知，也允许内部复用单发行详情请求；不要求上游拥有独立的轻量 API。版本浏览为可选能力，只有用户展开才调用。

快照分 `GroupSnapshot`、`ReleaseSnapshot`、`TrackSnapshot`，共享 `Field<T>{state: unknown | empty | value, value}` 与来源、层级、时间、完整性标记。候选明确使用 `AlbumCredit`、`ReleaseTrackTotal`、`MediumTrackTotal`，废弃模糊的 `TrackTotal`。摘要是这些字段的子集，不建立另一套含义。清单完整性单独记录，截断长度不能冒充发行总数。

| 来源 | 快照解析决定 |
|---|---|
| MusicBrainz | 分开读发行与组的 artist-credit；发行总数取声明总数或完整媒体摘要之和；保留全部标签/目录号、ISRC、作品 ISWC、条码；注释放发行事实 |
| iTunes | 专辑署名/总数从 collection 对象读取，歌曲署名从 track 读取；storefront 留在身份/请求上下文，不作为发行国家；清单截断保持 partial |
| QQ 音乐 | 专辑 singerList 与歌曲 singer 分开；专辑艺术家不写成歌曲角色；保留现有碟序与碟内序号转换；未核实 recordNum 不解释为目录号 |
| 标识与条码 | 以有类型的数组保存 ISRC/ISWC/UPC/EAN/GTIN 等明确提供的数据，保留原文；草案的“GTI”不被强行推断成另一编号，没有可靠字段就保持未知 |

`RefCodec` 负责链接解析、地区、规范化、格式提示及精确目标构造；通用层不拆 `country:id`。能力元数据驱动编辑、复核、候选及通用设置控件；复杂来源配置可留在对应来源表单，避免制造通用配置 DSL。

封面策略以稳定来源 ID 注册并注入 `covers`，通用调度只执行目录/策略；CAA、iTunes、QQ 的特殊推导留在来源适配器。把 `SetITunesDetailLoader` 等命名钩子改为统一接口，移除 store 对具体上游的 import。保留现有图片池、配额、出网、缓存、同键合并和采用语义。封面搜索保持独立来源注册表，163 不必实现歌曲搜索。

不采用“每个上游直接写库”：它会重复唯一性、归组、来源保护和索引维护。也不要求所有来源实现全部可选能力，缺能力有显式状态。

### 2. 三层身份与独立当前值表

建议核心表如下，名字可在实施时按仓库习惯微调，归属和约束不可改变：

| 表/数据 | 职责与约束 |
|---|---|
| `release_group` | 本地稳定 ID、展示来源、展示代表、revision；一个组可有多个成员 |
| `release_group_ref` / `release_group_snapshot` | `(provider, group_ref)` 唯一映射及各来源事实；未批准的新映射只在提议中 |
| `release_group_current` | 组标题、署名、类型摘要可空及来源；首个发行初始化，后加成员不覆盖摘要 |
| `release` | 组外键非空，来源与发行标识成对为空/非空；`(provider, release_ref)` 非空时唯一；revision |
| `release_current` | 一对一可编辑发行字段、每碟可空曲数、采用引用与逐字段状态 |
| `release_snapshot` / `release_snapshot_track` | 绑定发行事实与清单；清单按发行+碟号+位置唯一，与收藏外键解耦 |
| `track` | 可空发行外键、来源曲目身份、匹配时间、补全状态、revision；`(provider, track_ref)` 非空时全库唯一 |
| `track_current` / `track_snapshot` | 当前可编辑歌曲字段与独立只读事实，均不重复存专辑名 |
| 当前署名/角色及标识索引 | 原文区间、成员、角色来源及顺序；录音/ISRC/ISWC 可查询但不设收藏唯一约束 |
| `release_group_match_key` | 非唯一名称署名检索键，记录原始来源、normalizer 版本；可以重建 |
| `group_change_proposal` | 后台发现的关系建议、证据、基线 revision 和处理状态，补全成功不删除 |
| `release_membership_decision` | 提交时保存批准过的具体关系动作和证据，用于解释当前归属 |
| 歌词/图片文件索引 | 文件路径、哈希、内容类型、引用、来源、状态及创建时间 |

将可编辑数据放入 `*_current`，而非只在混合表上换一套锁字段，满足独立存储要求并使只读事实不会被编辑 API 意外改写。当前状态用规范字段键及有类型结构表达 `follow | user`、来源和显式空值；不再分别传易漂移的 sources/locked JSON。每次事务更新受影响实体 revision。

缺少曲名、署名、专辑名允许 NULL。只有有效发行身份或用户明确编辑发行资料（含类型/结构/封面）时才需要发行实体；一首完全没有发行资料的曲目保持 `release_id = NULL`。已有上游身份的无名发行仍可保存。同名空白不当身份，不把“未知专辑”占位字符串写库。

保留全库来源+曲目标识唯一，而非草案中按 release 放宽：当前三个来源均以现有精确曲目标识识别收藏，放宽会允许错误归属制造重复。同 recording 的不同 track 身份仍可各自收藏。

### 3. 同步规则与读侧

统一 `ApplySnapshot` 在一个事务内完成：验证目标身份/修订 → 合并已提供快照字段 → 更新 follow 字段 → 重建必要署名/角色/标识投影与 FTS → 更新补全状态和 revision。删除 `WriteDetailColumns` 与元数据编辑双路径，旧公共写入口不得绕开这一流程。

字段状态规则：

- unknown 不覆盖更完整旧事实；明确 empty 才能清空跟随字段。
- user 字段永不被自动补全覆盖，演唱/作词/作曲逐角色保护；只读其他角色按快照事实更新。
- 用户显式保存某字段时，等于有效上游已知值则 follow，否则 user；未触碰保留状态。换绑但未应用的保留值重新判定，不自动转 follow。
- 清除绑定后当前值保留并成为 user，旧快照不再作为有效上游列或名称键。
- 年份默认来自所属发行，发行日期变化只更新关联的 follow 年份；当前曲目的手改年份与其他歌曲独立。
- 跟随同步只更新事实/值，不拥有迁组权限。名称键变化可以产生提议，不能改变实体归属。

曲库、详情、艺术家、搜索和导出共用当前投影；使用所属发行事实，不读取展示代表的年份、厂牌或封面冒充当前曲目。FTS 接受空字段，正文与歌词不加索引。角色空响应与字段未提供要分别处理，CV 解析继续保留整体身份，不从署名补造演唱。

### 4. 判组、自动选版与准入是三个步骤

`ResolveGroup` 同时计算原生组映射与名称署名键的证据并集，也在候选集合中执行。名称键仅 NFKC、case folding、空白统一，必须两项非空；源包括组当前值、成员当前值和有效绑定快照。一个来源可生成多个证据项，索引键应含 source kind 与身份，不只用 group id。

- 单组命中：得到目标组，不等于已获成员批准。
- 无命中且证据足够：可以建立新组。
- 信息不足：自动决策按需补摘要，仍不足进入复核；交互保存可以直接选择保存未知资料，按独立本地组/无发行保存，不引入基本字段必填。
- 多组命中：返回全部证据，提供修正资料或明确合组预览。合组明确列来源组、目标组、迁移成员和身份映射，确认后以单事务完成；不自动选组。
- 后台首次发现新证据：保存 `pending_group_change`，详情/专辑显示待处理入口，进入相同冲突/成员预览流程。允许保持待处理，不因此阻断普通字段保存。

`SelectCandidate` 是纯决策，接收高置信候选、组证据和库内发行集合。多候选自动选择须证明同组、同曲目内容且非同发行内多个未决位置；MB 可用同 recording，跨来源缺可靠内容身份时交用户。候选内库内发行优先，然后发行总曲数降序、已知非 XW 优先、`(provider, releaseRef, trackRef)` 稳定排序。未知总数需要比较时补摘要或复核，只有一个候选不为排序多请求。显式选曲完全保留选择。旧载体/国家设置只标为展示代表偏好。

`PrepareAdmission` 与 `PlanEditSave` 复用同一成员检查，入口包括导入 runner、搜索 AddToLibrary、复核 AcceptCandidate/无需匹配、AddGhostRowToLibrary、手动创建、编辑、关系提议处理。确认动作不能只是 `force=true`：

```text
确定目标及草稿 → 读取/补充目标摘要 → 判组
  → 得到不可变计划（基线、字段变化、关系动作、影响）
  → 需要时展示影响确认及独立的新增发行确认
  → 提交时重新判组、检查成员及身份唯一性
  → 一次事务保存，或返回可重新预览的冲突
```

计划用服务端短期仓库存储（默认 15 分钟，重启后未提交计划失效），确认凭据绑定 plan ID 和内容哈希，不能批准未来动作。成功提交结果以幂等键记录，重复请求返回结果。即使新增组原先不存在，提交时也重新查名称/身份；SQLite 写事务内串行化最终决策，不能只检验准备时已有行 revision。没有有效批准时返回 `confirmation_required`，修改/过期返回 `plan_stale`，均无部分更新。导入条目终态与收藏同一事务写入。

### 5. 两栏编辑会话与“使用”

沿用大号 Volt 模态 `min(1280px, 96vw) × min(860px, 92vh)`，左 42%、右 58%，内部独立滚动、底栏固定；窄屏上下排列。尺寸是实施默认值，需原生验证可读性。

```text
编辑曲目                                                  关闭
左：上游信息                     右：当前信息
[来源下拉] [搜索]                [绑定修改/清除/重新获取] [使用]
搜索条件 / 候选列表              歌曲身份 · 具体发行 · 本地组
歌曲信息                        歌曲字段  当前值  上游值  无标题动作
专辑信息 / 来源版本选择          专辑字段  当前值  上游值  无标题动作
  当前发行曲目（可展开）         当前发行其他 N 首 · 同组其他发行 M 首
                                其他事实（只读、可折叠）
                                                 [取消] [保存]
```

草稿由 `useEditDraft` 管理三个独立对象：不可变 `baseSession`、左侧 `preview`、当前 `draft`。左侧选候选只改 preview，右侧上游列来自当前有效绑定草稿；避免浏览候选就把当前值或身份弄脏。每次请求以会话+候选 generation 标记，切换后取消旧请求并忽略迟到结果。

右侧顶部使用始终面向左侧选定预览，即使仍为当前绑定也可用。先固定候选和预览 revision，弹框文案：

> 将把当前上游提供的歌曲和专辑信息全部填入当前编辑值，并替换已有的手工修改。未提供的信息将保留；上游明确为空的字段将清空。修改只在点击保存后写入数据库。

确认才一次 reducer 更新绑定、目标发行、上游列和所有有确定值的可编辑字段，包括歌词/封面引用；默认不跳过 user 字段。未提供的图像或歌词不当清除，真实空值/空列表与未知区别呈现。取消不改变 draft。使用只处理当前曲目的草稿，其他歌曲保护规则在影响页中单独展示。底部不存在第二个整体填充动作。

手动修改绑定通过 RefCodec 解析为目标预览，显式选用后建立身份草稿；若仅修改绑定而不填字段，旧字段保留并在保存时重判 follow 状态。重新获取只更新会话暂存快照和上游列，不能走当前 `RefreshTrackDetail` 直接写库。逐字段应用/撤销保留，撤销以 baseSession 为基线。

字段编辑器：文本、可空正整数/年份、类型选择、艺术家有序标签、每碟曲数列表、歌词长文本对照、封面缩略图/本地选择/清除。歌词和图片文件可以先进入临时区，编辑器不调用已生效的采用/清除 API。没有发行时编辑封面会准备本地发行草稿，仍允许专辑名为空。

dirty 比较包含值、绑定、归属意图、角色、文件动作与跟随模式；搜索条件和左侧预览不计 dirty。退出统一保存/不保存/继续编辑；嵌套取消保留底层草稿，Esc 只交给 dialogStack 顶层，遮罩不直接丢弃。

### 6. 共享影响与换版保存

后端建议用三个阶段而非逐字段提交：

| 接口 | 输出与约束 |
|---|---|
| `GetEditSession` | 当前三层关系、字段、快照、能力、其他歌曲计数、revision；离线可用 |
| `SearchEditCandidates` / `LoadEditUpstream` | 纯搜索/预览数据，网络缓存可以更新，正式实体不变 |
| `PreviewEditSave` | 检查所有发行字段/封面/绑定的共享影响，返回新建、复用、修改全部的可行范围 |
| `PlanAlbumChange` | 当前发行歌曲及必要目标歌曲的字段差异、对应建议、未移动项和冲突 |
| `PlanEditSave` | 确定字段、关系和文件动作，复用准入服务生成最终计划 |
| `ConfirmReleaseAdditions` / `SaveEdit` | 记录仅适用于此计划的批准，再按最新关系重验提交 |

有共享影响则给出“新建专辑 / 修改全部 / 取消”。新建只移动当前曲目；上游精确目标已存在时该项显示移入具体发行，默认复用目标当前值，不能在移动时覆盖目标用户字段。纯本地新建不复制原来源身份；绑定发行不能原地把 A 的 releaseRef 改成 B，必须创建/复用 B 再移动。

“修改全部”页左侧第一项为发行变化，下面为当前发行的受影响歌曲；右侧展示前后值、对应证据、保留用户值、未对应原因。若要修改目标已有发行的当前字段，其现有歌曲必须也出现在预览。确认页底部确认只完成影响方案，仍有新增成员动作时继续独立确认；取消返回草稿。

换版对应优先精确身份、同来源录音、ISRC，文本+时长只给建议；同录音多位置不以序号消歧。用户可选择对应目标或留在原发行；目标已收藏、两个源占同一目标都作为冲突，不自动删收藏。未移动歌曲保持原发行快照、年份和位置；目标多出的清单位置不自动收藏。仅手工调整碟数时提供逐曲新位置/清空位置方案，已知越界或重复须处理，未知值允许保留。不能按数组序号推测身份。

解除整个发行绑定同步清除该发行所有歌曲身份并保留当前值；只解除部分则新建本地发行并移动相应歌曲。两类都经影响预览，不留下来源相互矛盾的持久关系。

### 7. 文件、事务与回收

歌词目录默认应用目录下 `lyrics/`，当前文件以曲目 ID 与内容哈希区分，保存 UTF-8 原文。封面沿用按 release ID 隔离的目录及实际来源命名，新内容使用不可变路径/稳定后缀，旧引用不提前删除。

保存步骤：临时准备与校验 → 最终路径可用 → SQL 事务验证计划并切换引用 → 提交成功发布事件 → 清理无引用旧文件。失败清理本次新增无引用文件；启动按引用表清理中断残留。文件准备阶段不能提前覆盖仍被其他曲目使用的文件，引用不以文件是否刚创建推断。封面清除作为引用状态提交，文件删除在安全回收阶段；保留现有独立详情入口的显式采用行为，但与编辑保存共用文件服务。

SQLite 事务不能回滚文件系统，故不声称跨系统原子事务；以不可变文件、事务引用和补偿清理保证用户看到旧完整状态或新完整状态。网络不在写事务中执行。

### 8. 多版本读侧与验证证据

专辑 DTO 返回本地组摘要及各成员发行，不再用 `mergeAlbumGroups` 拼凑某一代表的歌曲清单。每个发行使用自己的当前值、快照、封面及清单；未展开清单也能看到该版本收藏。组显示“收藏 N 首 · M 个在库版本”，上游版本数另列。空上游发行可不默认展示，但仍算库内成员；UI 在显示 M 时说明包含已保存空发行，或同时提供收藏版本数，避免计数不一致。

采用现有 fixture 和保存的 MB 原始响应构建可提交测试样本，不依赖 `tmp/` 在他人机器存在。本轮核对的响应事实：

| 源 → 目标 | 应验证结果 |
|---|---|
| `0bcd51de-dabe-4106-9118-716f67fef4db` → `8c4d9698-bcac-456a-a5ac-1bd90d64c4ff` | 14 → 15 首；White Love 位于 1-6；原 1-6～1-14 对应新 1-7～1-15 |
| `bb08c318-b5c2-426e-9c43-58c520ae116c` → `d642286a-4ff9-476a-8708-116176151f97` | 14 → 15 首；深愛位于 1-13；末两首后移；年份从 2014 到 2012 仅更新实际移动的 follow 字段 |

测试分层：来源契约与未知字段、隔离 SQLite 中真实 App 入口的准入/补全/保存、文件失败与并发、Vitest 草稿状态、Playwright 两浏览器用户流程。真实网络回归可显式启用，不能代替固定样本；原生文件选择、输入法、窄屏、退出和嵌套弹窗单独记录，未执行不写通过。

## Risks / Trade-offs

- [名称相同可能误归组，翻译不同可能漏配] → 展示双路径证据，名称键非唯一，多组冲突交显式方案；不用模糊匹配扩展范围。
- [判组摘要增加交互延迟] → 按发行去重缓存，只补缺字段，取消贯穿；未知资料可交互保存，网络错误单独提示。
- [共享快照变更使编辑计划过期] → revision 覆盖歌曲、源目标发行、组和证据，保留草稿重新预览，允许交互请求优先。
- [用户使用操作会替换当前手工值] → 确认文案具体说明、原子草稿更新、逐行撤销，保存前不落库。
- [来源能力与返回资料不一致] → 能力和字段状态分开；保留 QQ 离线样本和错误语义，iTunes 截断不冒充完整。
- [模型与接口改动较大] → 按任务依赖推进，过渡适配器只能委托统一服务；检查所有能创建发行/改归属的写入口。
- [文件回收及共享引用竞态] → 不可变文件、提交后回收与启动清理；引用仍生效时禁止删除。
- [旧库误开] → 新结构使用独立模型代际标识并在迁移前验证，避免仅重写 migration 1 导致版本号相同却结构不同。

## Migration Plan

1. 实施时引入新快照契约和来源适配，随后完成新模型初始结构与显式模型代际检测；每阶段保持必要调用方可编译。
2. 切换全部写入口到计划与统一同步，再切换读侧、生成 Wails 绑定和新编辑器；完成后移除旧直接写入口、锁机制及旧封面转换路径。
3. 在隔离新库完成自动回归和 Wails 构建，记录原生验收。用户在测试前清空历史应用数据，本变更不执行删除。
4. 回退代码版本需要使用与其匹配的独立数据目录或再次空库初始化，不设计新旧库双向转换。
5. 实施验证完成后再同步主规格、架构、README 和 known gaps，更新已失效 Purpose/当前限制说明；规划产物不能作为完成证明。
