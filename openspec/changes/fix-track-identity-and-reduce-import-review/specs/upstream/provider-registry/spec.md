# Spec Delta

## ADDED Requirements

### Requirement: 候选精确身份与决策资料契约
元数据来源 SHALL 按其登记能力为业务提供候选的精确身份状态、有效发行关系及必要的决策资料，区分精确 track、未解析候选、歧义、资料不足和来源错误。身份解析不得将 Recording 或 ISRC 当作 track 等价。业务提交通用候选及位置要求，不构造平台专用标识或解释原生响应；不同来源分别解析自身 ID 和返回完整性，未提供能力时明确返回不支持，不伪报为空结果或精确成功。

#### Scenario: MusicBrainz 缺少 track
- **WHEN** 业务收到缺少真实位置的 MusicBrainz 候选并要求确认目标
- **THEN** MusicBrainz 能力返回真实位置或明确的歧义/不足结果，业务无需识别 recording@release 字符串格式

#### Scenario: 已有精确来源身份
- **WHEN** iTunes 或 QQ 音乐候选已经具有来源有效的歌曲及专辑身份
- **THEN** 来源按自己的规则验证并返回精确目标，不要求业务按来源分支解析 ID，不增加无必要的远程请求

#### Scenario: 不支持位置补取
- **WHEN** 来源不能把一个未解析候选定位到精确 track
- **THEN** 返回不支持或资料不足，业务保留复核，不借另一首同 ISRC 歌曲充当目标

### Requirement: 决策资料不等于收藏或身份映射
来源返回的摘要、清单和候选身份解析 SHALL 仅提供事实及完整性，不自行决定本地已收藏、不创建收藏、不写入跨来源 track 映射，也不把用户查询填进上游快照。自动偏好、输入是否满足和本地精确跳过由业务规则处理；完整详情补全继续只更新已经核验的有效绑定。

#### Scenario: 不同来源相同 ISRC
- **WHEN** 两个来源的候选共享 ISRC 但没有相同的来源精确 track 身份
- **THEN** 各来源保留各自事实，不自动生成等价绑定或让其中一个候选失去添加权限

#### Scenario: 查询中包含译名
- **WHEN** 输入译名帮助定位候选而来源事实没有该译名
- **THEN** 译名只作为输入比较证据，不被复制进上游曲目或发行快照
