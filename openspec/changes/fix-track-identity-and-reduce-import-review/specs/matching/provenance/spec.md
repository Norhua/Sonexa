# Spec Delta

## MODIFIED Requirements

### Requirement: 身份与唯一性
曲目 SHALL 可保存 match_source、match_ref、matched_at；来源和精确曲目标识组合在有来源时唯一，无需匹配时为空。MusicBrainz 使用真实 track MBID，iTunes 使用小写 country:trackId，QQ 音乐使用歌曲 MID，并核验曲目与具体发行关系。MusicBrainz 搜索缺少位置时可展示 recording@release 合成候选，但新收藏前必须解析真实 track。Recording、ISRC 不构成收藏唯一约束，亦不作为跨来源自动实体统一依据。

#### Scenario: 同录音不同版本
- **WHEN** 同录音出现于 CD 和数字发行的不同 track
- **THEN** 两者匹配身份不同，可以分别收藏；不能仅按 recording 判为同一清单位置

#### Scenario: 同 ISRC 的不同专辑
- **WHEN** 库中已有特典 CD 的 track，合集中的另一 track 与其共享 ISRC
- **THEN** 合集 track 仍可接受或加入曲库，不影响原收藏的发行、字段和组织关系

#### Scenario: 合成候选不能成为精确收藏
- **WHEN** 候选仅有 recording@release，尚未确定真实曲目位置
- **THEN** 不以合成标识创建新收藏或判定已有；按来源能力解析位置，仍有歧义则保留待处理

### Requirement: 候选本地识别
候选 SHALL 仅在其来源和精确 track 标识与有效本地绑定一致、发行关系无冲突时显示本地已存在。ISRC、Recording、文本和时长相似只能用于输入匹配证据或相关信息，不得填充候选的已收藏目标、显示本地徽章或改变添加权限。身份或本地查询失败须明确报错，不伪装为未收藏。候选图片仍由候选自己的发行身份定位。

#### Scenario: ISRC 与文本命中
- **WHEN** 标识未命中但 ISRC 相同，或无来源曲目的文本相同
- **THEN** 上游候选仍未被判定已收藏，复核显示接受、搜索显示加入曲库，不提供合并

#### Scenario: 精确标识命中
- **WHEN** 来源与 track 标识和发行关系均与已有收藏一致
- **THEN** 显示本地及上游徽章，复核候选动作是跳过，搜索动作是已在库中并支持查看已有曲目

#### Scenario: 来源或发行冲突
- **WHEN** 字符串标识相同但来源不同，或同来源曲目标识携带的发行与有效绑定冲突
- **THEN** 前者不视为相同收藏；后者报告身份冲突，不把冲突候选当作可自动跳过的目标

### Requirement: 重复入库处理
显示候选时 SHALL 查询当前本地状态；搜索中精确已有曲目显示已在库中，有本地标识时可跳转。接受及跳过在提交时重新校验精确身份、发行关系和队列修订。接受时目标已存在则返回已有收藏并把对应输入记为已存在跳过，不创建第二条，不更新旧收藏；跳过时目标已不存在或绑定改变则拒绝结束条目并要求刷新。重复请求保持幂等，不能恢复已处理状态。

#### Scenario: 并发加入
- **WHEN** 搜索和复核几乎同时加入同一来源同一标识
- **THEN** 最终仅一条收藏，后一次返回已有曲目身份，复核输入按已存在跳过结束，不显示唯一键错误

#### Scenario: 跳过前删除或换绑
- **WHEN** 候选显示跳过后，原收藏被删除或换成另一 track
- **THEN** 提交跳过失败且条目仍可处理，刷新后根据当前绑定重算动作，不悄悄丢弃输入

#### Scenario: 接受其他专辑的同录音 track
- **WHEN** 用户明确接受未收藏的另一个专辑 track，库中已有同 Recording 或 ISRC 的曲目
- **THEN** 以所选 track 执行准入，不替换成旧收藏；所需发行成员确认仍生效
