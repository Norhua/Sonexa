# Spec Delta

## MODIFIED Requirements

### Requirement: 补全与复核状态
曲目 SHALL 保存 pending、fetched、absent、skipped 及补全失败次数、原因；有可补全曲目和发行身份时为 pending，暂不能精确补全为 absent，本地无需匹配为 skipped。原始导入行不可变；复核保留目标歧义、版本或位置冲突、资料不足、未匹配、新发行加入已有组、判组资料不足或组证据冲突等结构化原因与可读证据。输入的已存在跳过独立于曲目补全状态，不修改已有曲目的补全信息。署名待确认及待处理归组提议独立保存，补全成功不得清除它们。

#### Scenario: 失败与进度
- **WHEN** 补全失败或查询进度
- **THEN** 失败保留 pending 并累计次数；进度只统计本轮待补集合，历史 fetched/absent 及 skipped 不进入分母，完成一首递增一首

#### Scenario: 当前待补集合
- **WHEN** 全库已有 9 首完成补全，另有 3 首 pending
- **THEN** 补全入口仅在全部曲目页显示 0/3，pending 清零即隐藏；达到重试上限但仍为 pending 时继续保留入口

#### Scenario: 工作集延续与重置
- **WHEN** 本轮新增待补、暂停、让路、失败或重试，或开始下一批或重启应用
- **THEN** 新待补加入当前集合，暂停和重试保留进度；一轮结束后下一批从零开始，重启只以剩余 pending 建立新集合

#### Scenario: 后续补全成功
- **WHEN** 有待处理归组提议的曲目补全成功
- **THEN** 清理本次网络错误，继续保留归组提议与署名待确认状态

#### Scenario: 跳过重复输入不重置补全
- **WHEN** 已收藏 track 正在等待补全，再次导入识别到同一精确 track
- **THEN** 输入记已存在跳过，原曲目补全状态、失败次数、用户字段和匹配时间不改变

## ADDED Requirements

### Requirement: 原始行与活跃问题分离
存储 SHALL 保留每个批次的有效原始行、解析值、独立状态及终态目标，并另外保存活跃语义问题和成员关系。每行同时最多属于一个活跃问题；问题保留当前等价证据、版本和修订，支持归并、拆分及重启恢复。归并不删除原始行、不改变各批次行数，不把终态输入作为未来输入的身份依据，且不将问题归并等同于收藏实体合并。

#### Scenario: 同问题跨批次
- **WHEN** 两批次原始行经语义证明属于同一活跃问题
- **THEN** 保留两行原文及各自批次状态，复核读取一个问题及两份来源；重启后关系保持一致

#### Scenario: 并发建立相同问题
- **WHEN** 两批次同时处理可证明等价的输入
- **THEN** 事务提交后只有一个相应活跃问题，不丢失任何来源行，不产生一行多归属

#### Scenario: 缺失字段相同
- **WHEN** 两行缺少基本信息且没有充分证据证明同一目标
- **THEN** 不因空文本或空标识相同归并，仍保留独立可处理输入

### Requirement: 可重建的当前匹配证据
名称、别名、版本和目标候选索引 SHALL 来源于当前输入、当前收藏值、有效绑定快照或明确获取的来源事实，保留证据类型及规则版本并支持重建。旧绑定快照、过期队列修订和未知注释不得充当有效正证据。历史操作记录可以保留用于诊断和重复提交幂等，但不得作为新输入的自动选版映射；删除历史导入记录不改变当前音乐身份识别结果。

#### Scenario: 不依赖旧批次
- **WHEN** 保留当前曲库和有效事实、移除已完成的历史导入记录后导入一份带可靠译名的表格
- **THEN** 相同 track 仍能通过当前证据被识别，结果不因旧批次不存在而退化为必须复核

#### Scenario: 换绑与规则更新
- **WHEN** 收藏换绑，或匹配证据规则版本更新
- **THEN** 原绑定证据失效或索引重建；读取与提交不得使用失效证据自动跳过新的输入

### Requirement: 队列终态原因与一致性
输入 SHALL 分开记录处理状态、处理原因、实际目标及问题修订；已存在跳过不得计为新增，不再新增 merged 终态或依赖 merged_into 进行候选动作。接受、跳过、移出与重搜须校验当前状态和修订，旧请求不得恢复终态。多行提交、问题关系和批次统计保持事务一致，失败不留下部分完成。

#### Scenario: 精确重复与一般移出
- **WHEN** 一行因精确已有 track 被跳过，另一行被用户移出队列
- **THEN** 两者具有不同原因和统计，前者可指向当次核验的目标，后者不伪称已有收藏

#### Scenario: 迟到重搜
- **WHEN** 接受或跳过已提交，先前重搜结果随后返回
- **THEN** 旧结果不能把该行改回 review，问题和全局计数保持已提交结果
