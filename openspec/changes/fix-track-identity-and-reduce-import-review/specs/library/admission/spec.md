# Spec Delta

## MODIFIED Requirements

### Requirement: 原子结果与重复请求
一次提交 SHALL 原子保存曲目、发行、组映射、当前字段、快照、来源状态、艺术家关系、索引和对应导入/复核终态。精确来源曲目身份已存在且发行关系一致时返回已有收藏，不创建或更新旧收藏，对应输入按已存在跳过结束；不同 track 不因同 Recording/ISRC 复用旧收藏。重复提交同一成功计划返回同一结果。任何校验、数据库或文件准备失败均不得留下部分关系或错误终态。

#### Scenario: 接受保存失败
- **WHEN** 复核接受已获确认但提交前文件准备或事务写入失败
- **THEN** 全部批准范围内的输入仍可处理，旧收藏数据和文件引用保持有效，不显示已接受

#### Scenario: 两个入口加入同一身份
- **WHEN** 搜索和复核并发加入同一来源同一曲目标识
- **THEN** 最终只有一条收藏，两入口均可得到已有收藏身份，只有真正创建者计新增，复核重复输入计已存在跳过

#### Scenario: 同录音不同 track
- **WHEN** 用户接受另一个专辑中的 track，库中已有相同 Recording 或 ISRC 的收藏
- **THEN** 为所选 track 执行独立准入和保存，所需成员确认仍生效，不调用旧合并逻辑替代创建

## ADDED Requirements

### Requirement: 精确跳过的原子校验
跳过 SHALL 绑定到待处理输入范围、候选精确来源/track/发行身份及预期修订，在事务内验证该身份仍有有效本地收藏、输入仍未完成且请求仍属于当前问题。成功只保存跳过终态、目标和原因，不修改收藏、来源、时间、快照、发行成员或文件；不需要新增发行确认。目标消失、换绑、发行不一致或范围变更时拒绝跳过，问题保持可处理。

#### Scenario: 跳过时目标仍存在
- **WHEN** 用户选择跳过且精确绑定、队列与范围修订均有效
- **THEN** 输入原子结束，返回已存在目标，曲目数量、首次加入时间和用户字段全部不变

#### Scenario: 目标消失或绑定改变
- **WHEN** 用户点击跳过前已有收藏删除、换绑或发行关系改变
- **THEN** 返回可刷新处理的冲突，不把输入标记完成，不改为自动接受其他候选

#### Scenario: 接受请求晚于另一项跳过
- **WHEN** 同一输入已被有效跳过，旧接受或改搜请求随后提交
- **THEN** 旧请求不得再创建收藏、改变终态或恢复待处理；重复的同一成功操作只返回原结果

### Requirement: 问题成员批准范围
多行问题的接受或跳过 SHALL 将明确列出的成员、各输入修订、问题修订和等价证据纳入批准范围。提交重验全部成员仍等价且未完成；成员变化或拆分时整个请求失败，不部分结束。一次接受最多新建一个精确 track，确定一个来源行为创建者，其余精确重复行记已存在跳过。未来相似输入不继承本次批准，其他问题只能依当前规则重新判断。

#### Scenario: 多来源一次接受
- **WHEN** 两个批次的等价输入在同一批准范围内接受未收藏 track
- **THEN** 新收藏与两行结果同事务提交，一行记新增、另一行记已存在跳过，各批次统计更新且只有一份收藏

#### Scenario: 确认期间成员变化
- **WHEN** 确认弹窗打开后问题加入新成员或一行被拆出
- **THEN** 旧批准不能用于新范围，返回冲突且不部分入库，用户可查看新范围重新确认

#### Scenario: 不同输入的新发行确认
- **WHEN** 另一问题也需要新增相同发行，但未包含在当前批准范围内
- **THEN** 不复用当前问题的批准；按提交时的当前成员状态重新准备自己的计划，不把历史确认当作自动选版证据
