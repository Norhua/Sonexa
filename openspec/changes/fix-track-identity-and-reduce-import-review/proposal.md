# Proposal

## Why

当前候选把 ISRC 命中当成“本地已存在”，复核页的“合并”和搜索页的“已在库中”因此阻止收藏同一录音在不同专辑中的 track，与项目按 track 收藏的模型冲突。同时，导入未充分利用译名、专辑、版本、位置和时长证据，格式不同的相同输入反复进入复核，明确不同专辑的候选也会制造无谓歧义。

## What Changes

- **BREAKING**：候选已收藏状态只认来源与精确 track 身份，并核验发行关系；ISRC、Recording 和文本相似不再使上游候选显示本地、跳过或失去添加权限。复核候选动作由“接受/合并”改为“接受/跳过”，搜索页同步采用精确身份规则。
- 明确“接受”收藏用户选中的 track，“跳过”仅在该 track 已绑定时结束导入条目，不合并实体、不换绑、不更新已有收藏。提交时重验身份和队列修订，处理并发接受、删除、换绑及迟到请求。
- 新建本次输入的结构化匹配证据：统一曲名、艺术家、专辑的可靠译名/异写比较，保留录音版本、发行后缀、角色和合作信息；未知注释不作为自动等同依据。年份、碟号、轨号、时长参与决策，不以搜索用的简化串作为身份。
- 本地当前值及有效绑定快照与上游结果共同提供候选。先依据本次输入收敛目标专辑、录音版本和位置，再选择具体 track，最后判断是否已收藏；本地仅召回一首、同 ISRC 或最高分本身都不足以自动跳过。
- **BREAKING**：替换“多条高置信只要跨组就复核”的无条件规则。能由输入排除其他专辑的候选不再制造自动决策歧义；仍跨组或存在版本、位置、资料冲突时保持复核。只在同组同内容且输入未指定细发行时优先已收藏的兼容 track，其次沿用已有发行、总曲数等选版规则；新增发行准入确认保持不变。
- MusicBrainz 缺少真实位置的合成候选可以展示，但新收藏或自动跳过前须通过目标发行清单定位真实 track；无法唯一定位时保留复核，不能把 recording@release 当作精确位置。
- 将能证明表达相同歌曲、目标专辑和版本要求的活跃输入归为一个复核问题，保留各批次原始行及独立统计。候选集合重叠、相同录音、缺失与明确版本的包含关系不能成为归并依据。收藏变更后按当前证据重评相关待办，安全消除已解决问题。
- 区分新增收藏、已存在跳过、待复核原始行数与独立复核问题数，提供可读判断依据。不增加“历史输入 → 上次选择”的决策缓存，不按文件指纹或原始行相等决定音乐身份。

## Capabilities

### New Capabilities

无。复用现有匹配、复核、准入和存储能力边界。

### Modified Capabilities

- `matching/provenance`：精确 track 收藏判断、跨发行可共存、接受/跳过与写入竞态规则。
- `matching/text-processing`：面向本次输入的有类型文本证据、可靠异写、完整版本限定和查询/身份分离。
- `matching/confidence`：保留展示评分，新增更严格的元数据自动决策证据；专辑、版本、位置和时长冲突不可被分数抵消，隔离独立歌词规则。
- `matching/pipeline`：本地及上游候选解析、先限定目标再选版、精确跳过、活跃待办重评和统计口径。
- `review/review-queue`：候选接受/跳过、语义相同待办归并、来源展开、解释与请求/确认归属。
- `library/admission`：接受已存在目标转跳过、跳过与多行终态原子提交，不改变既有收藏或绕过新增发行确认。
- `platform/data-store`：输入证据与活跃问题关系、修订和跳过原因、可重建索引；不保存可复用的历史选版结论。
- `platform/app-shell`：共享候选动作和精确本地徽章、独立复核问题计数及原始行计数展示。
- `upstream/musicbrainz`：合成候选的真实位置解析、同发行重复录音歧义与有界清单获取。
- `upstream/provider-registry`：业务侧声明并注入候选身份解析/决策资料能力，上游解释自己的身份与完整性，不在业务层按来源分支。

## Impact

- 后端：`internal/matching/`、`internal/importer/runner.go`、`internal/library/selection.go` 与准入服务、`internal/store/{lookup,queue,admission_plan,grouping,migrations}.go`，以及 `internal/app/bindings_{review,upstream,import}.go` 和事件装配。
- 上游：`internal/provider/musicbrainz/` 解析精确位置与提供完整性证据；其他元数据上游按能力返回已有精确身份或明确不支持。保留既有共享配额、缓存与出网门禁，不引入外部 AI、翻译或音频指纹服务。
- 前端及绑定：`ReviewView.vue`、`SearchView.vue`、`ImportQueueView.vue`、`CandidateTable.vue`、任务状态与 Wails 生成类型；移除 `MergeCandidate` 等旧候选合并协议。条目级无需匹配、移出、无一匹配及失败重试等辅助控制保留，两个选项限定为候选行的收藏决策。
- 数据：按当前开发阶段的新库规则调整队列/证据结构，不转换历史应用库；不改变来源+track 唯一约束，不新增 ISRC/Recording 唯一约束。
- 验证：覆盖真实业务入口的同 ISRC 不同专辑收藏、异写输入、截断专辑、版本/角色反例、跨批次语义归并、并发与迟到响应。已有“跨组一律复核”“合并”测试需按新规则替换，不能只改快照使测试通过。
- 与活动歌词变更隔离：新自动身份规则只用于音乐元数据；不改变歌词候选、Top 3 或自动预览策略，不修改另一活动变更的文档。
