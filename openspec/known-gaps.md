# 已知问题与未完成目标

本表只记录当前仍存在的问题。主规格描述现有行为；下列验收条件是待完成目标，不能由已有测试通过推定完成。修复后补充实际业务入口回归，并从本表删除对应条目。




## G04 — 设置的生效范围

- **现状**：`ReviewThreshold` 可在界面保存，但匹配引擎不读取；权重和相似度由后端配置读取，界面没有控件。`DefaultEncoding`、`DefaultDelimiter`、`MultiValueSep` 没有解析/导出流程的消费方，导入向导也没有多值分隔符控件。设置页按注册表列出分组，但专属字段仍按来源分支实现。
- **依据**：`internal/config/settings.go`、`internal/app/bindings_import.go`、`internal/matching/dispatch.go`、`frontend/src/views/SettingsView.vue`。
- **目标与验收**：明确保留参数的作用，删除无用途控件或完成实际使用；从保存设置到真实搜索、导入、导出验证行为变化。高置信继续使用曲名匹配且艺术家或歌集精确的条件，不改成分数线。

## G05 — 封面获取

- **现状**：列表封面没有视口优先调度。搜索和复核表格按结果顺序为全部候选批量预取缩略图，只在结果集改变或表格退出时取消不再需要的任务；滚出视口但尚未开始的任务不会取消或降级。曲库列表依靠图片懒加载按需请求。
- **依据**：`frontend/src/lib/useCandidateCovers.ts`、`internal/covers/pool.go`。
- **目标与验收**：视口内的行优先下载，滚出视口且未开始的任务取消或降级；用长结果列表验证首屏图片先完成、滚动后不再下载已离开的行，并保持同键合并与多消费者租约语义。


## G07 — 导出深度与大曲库

- **现状**：`frontend/src/App.vue` 固定导出 full，后端 basic 没有界面入口。`internal/store/library.go` 先从全文索引取最多 2000 个标识再筛选，前端没有分页、虚拟滚动或截断提示，也没有大曲库性能基准。
- **目标与验收**：提供导出字段深度选择；明确大结果分页或截断行为，验证与筛选、排序、选择和导出的组合。艺术家/专辑当前只有名单查找，若增加独立曲目搜索需另定布局。


## G09 — 出网控制与错误提示

- **现状**：封面的自动请求、预取、网络搜索、预览和采用已统一检查出网条件，并显示统一原因。`frontend/src/views/AlbumsView.vue` 的「重新获取」「补全清单」按钮仍未按出网状态禁用，只在点击后由 `FetchTracklist` 返回原因。设置、专辑、编辑、艺术家等页面仍各自显示局部错误提示；已有全局禁网、离线和普通错误已统一移至侧栏设置正上方，不再占用主内容顶部。
- **目标与验收**：联系方式为空时所有出网入口在界面上同样禁用，并显示统一原因与设置跳转；网络错误不伪装无结果，重复错误在统一位置合并提示。

## G11 — 不确定署名的专门人工确认

- **现状**：初次创建、手工编辑及补全已同步署名成员；不确定标记独立保存，成功补全不再清除。仍没有针对署名拆分结果的专门人工确认界面；普通编辑可修改署名与角色，不能替代成员边界确认。
- **目标与验收**：展示待确认的署名边界、允许用户明确成员及顺序，确认后同步区间与索引；遵循艺术家规格中的双 CV 署名成员及受限演唱兜底，不把普通署名或单独配音关系当作歌曲演唱证据。

## G12 — 清单数量上限

- **现状**：iTunes 的 `lookupLimit` 固定为 200，没有按声明总数追加获取。
- **目标与验收**：超过 200 条时提供完整获取方案或明确的不可取全提示，并保留 partial 状态。测试不能仅用 120 首样例证明任意长度清单完整。

## G13 — 标签排序

- **现状**：`frontend/src/stores/library.ts` 对歌单和标签均传 collectionId；`internal/store/library.go` 对该条件统一按集合 position 排序，没有区分种类。
- **目标与验收**：歌单默认恢复保存位置，标签忽略集合位置并采用普通曲目排序；验证从表头排序回到默认顺序及重新打开页面。

## G14 — 封面来源真实网络复测

- **现状**：QQ 搜索已改用 `u.y.qq.com/cgi-bin/musicu.fcg`（`DoSearchForQQMusicDesktop`），163 改用 WEAPI 歌曲搜索并按专辑聚合，2026-09-24 均已真实验通；CAA、iTunes 已完成真实搜索、预览和采用。原生窗口、输入法、文件选择及编辑相关人工验收已由用户于 2026-10-16 确认完成；此次确认不扩展为四来源的最新在线复测或真实断网专项证据。图片传输不使用环境代理，需要代理才能访问 archive.org 的网络无法获得直连加速。
- **依据**：`internal/provider/{caa,itunes,qqmusic,netease}/` 的封面能力实现、`internal/app/cover_live_test.go`；历史验收见归档变更 `revise-album-cover-workflow/acceptance.md`。
- **目标与验收**：用 `SONEXA_LIVE_COVERS=1 go test ./internal/app -run '^TestLiveCoverSources$' -count=1 -v` 定期复测四来源，可用 `SONEXA_COVER_SOURCE` 限定来源；不以离线 fixture 代替真实来源，原生人工确认与真实网络复测分别记录。

## G15 — 旧模型的用户迁移边界

- **现状**：当前开发版本采用 `upstream-snapshot-v1` 模型代际，只支持清空历史应用数据后的新库初始化。检测到旧模型明确拒绝打开，不自动删库，也不转换旧数据与旧采用文件。
- **验证边界**：空库、新模型事务迁移、文件引用回滚及目录切换已覆盖；这些证据不代表历史数据库可升级。若未来需要保留旧收藏升级，须另行规划数据与采用文件迁移，不恢复已删除的隐式转换。

## G16 — QQ 音乐上游

- **现状**：QQ 音乐使用非公开的 `musicu.fcg` 与歌词接口，契约可能不经通知改变。碟序规律（`index_cd` 从 0 开始、`index_album` 为全专辑序号）与字段语义来自少量样本，`recordNum` 未核实，因此不映射目录号。元数据、封面查询、手动歌词及回退已共用 `qq` 平台桶；合计 HTTP 记账、重试/回退与设置生效的离线测试已通过。元数据单碟、多碟、真实缺失歌词回退和有界速率网络入口已加入。2026-10-17 搜索及单碟/多碟详情实际通过（3 次请求，约 2 秒间隔，HTTP 200/业务码 0），但缺少实际触发歌词回退的样例；随后一次授权的有界查找（2 次搜索、4 个有效详情、6 次请求）也都返回内联歌词，未命中回退。四来源复测和 45/60 样本尚未运行；证据见 [verification.md](verification.md)，不能由这次部分成功关闭接口可用性风险。
- **依据**：`internal/provider/qqmusic/`、`internal/app/{cover_quota_test,qq_settings_test,qq_live_test}.go`；速率选择依据及非官方边界见[架构设计](design.md#上游能力与装配)。
- **目标与验收**：按 [README](../README.md#qq-元数据与有界速率验证) 显式开启有界样本，覆盖搜索、单碟、多碟详情及真实歌词回退，记录发送间隔、HTTP/业务错误与 Retry-After。回退需要实际缺少内联歌词的样例，不能篡改响应制造成功；遇限制停止，不继续提速。

## G17 — 独立歌词来源与回归边界

- **现状**：网易云、QQ、酷狗、酷我歌词均使用非公开接口。2026-10-16 实现计划记录四来源均有成功实测，也观察到 QQ `2001` 与酷我 `301` 波动；QQ 新端点已实测原文、翻译、罗马音与增强型 LRC，但不承诺每首歌或任意时刻可用。手动 QQ 歌词、元数据和封面查询现已共用平台配额；该离线验证不代表非公开接口的最新在线复测完成。
- **依据**：`internal/app/lyrics_sources_test.go` 的 `TestLiveSources`、`internal/provider/qqmusic/lyrics_probe_test.go`、`internal/app/lyrics_test.go`；最新同步与历史验证区分见 [verification.md](verification.md)。
- **格式范围**：本地只导入 UTF-8 TXT/LRC，不转码 GBK/UTF-16；在线只支持已实现的 QQ QRC 转换，不接入网易云 YRC、酷狗 KRC 或本地二进制 QRC/KRC。没有播放器/播放同步高亮与独立歌词导出 UI，这些不作为当前已交付能力。
- **回归限制**：第二次实现计划的全量 Playwright 为 241/242，编辑器“用户”徽标旧断言在基线也可复现；歌词定向回归通过不代表该失败已修复。歌词文件选择器只经过可注入 picker 与浏览器替身测试，没有新增原生人工验收。
- **目标与验收**：按 `SONEXA_LYRICS_LIVE=1 go test ./internal/app -run '^TestLiveSources$' -count=1 -v` 定期复测，使用 `SONEXA_LYRICS_SOURCE/TITLE/ARTIST/ALBUM/DURATION_MS` 限定样例并记录缺失、错误与部分成功；真实网络、原生选择器和既有浏览器断言分别取证，不以离线或桩测试代替。新增逐字格式或播放器需另行定范围。

## 验证范围

此前上游/编辑器的原生人工验收已由用户确认，不覆盖后续独立歌词变更，见 [verification.md](verification.md)。本次文档同步不新增截图或逐项原生实测结论；浏览器测试使用 Wails 替身，不能替代原生验证。大曲库性能与真实网络专项仍按各条目保留。
