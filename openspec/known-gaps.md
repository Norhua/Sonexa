# 已知问题与未完成目标

本表只记录当前仍存在的问题。主规格描述现有行为；下列验收条件是待完成目标，不能由已有测试通过推定完成。修复后补充实际业务入口回归，并从本表删除对应条目。




## G04 — 设置的生效范围

- **现状**：`ReviewThreshold` 可在界面保存，但匹配引擎不读取；权重和相似度由后端配置读取，界面没有控件。`DefaultEncoding`、`DefaultDelimiter`、`MultiValueSep` 没有解析/导出流程的消费方，导入向导也没有多值分隔符控件。设置页按注册表列出分组，但专属字段仍按来源分支实现。
- **依据**：`internal/config/settings.go`、`internal/app/bindings_import.go`、`internal/matching/dispatch.go`、`frontend/src/views/SettingsView.vue`。
- **目标与验收**：明确保留参数的作用，删除无用途控件或完成实际使用；从保存设置到真实搜索、导入、导出验证行为变化。高置信继续使用曲名匹配且艺术家或歌集精确的条件，不改成分数线。

## G05 — 封面获取

- **现状**：列表封面没有视口优先调度。搜索和复核表格按结果顺序为全部候选批量预取缩略图，只在结果集改变或表格退出时取消不再需要的任务；滚出视口但尚未开始的任务不会取消或降级。曲库列表依靠图片懒加载按需请求。
- **依据**：`frontend/src/lib/useCandidateCovers.ts`、`internal/covers/pool.go`。
- **目标与验收**：视口内的行优先下载，滚出视口且未开始的任务取消或降级；用长结果列表验证首屏图片先完成、滚动后不再下载已离开的行，并保持同键合并与多消费者租约语义。


## G07 — 导出深度与大曲库

- **现状**：`frontend/src/App.vue` 固定导出 full，后端 basic 没有界面入口。`internal/store/library.go` 先从全文索引取最多 2000 个标识再筛选，前端没有分页、虚拟滚动或截断提示，也没有大曲库性能基准。
- **目标与验收**：提供导出字段深度选择；明确大结果分页或截断行为，验证与筛选、排序、选择和导出的组合。艺术家/专辑当前只有名单查找，若增加独立曲目搜索需另定布局。


## G09 — 出网控制与错误提示

- **现状**：封面的自动请求、预取、网络搜索、预览和采用已统一检查出网条件，并显示统一原因。`frontend/src/views/AlbumsView.vue` 的「重新获取」「补全清单」按钮仍未按出网状态禁用，只在点击后由 `FetchTracklist` 返回原因。设置、专辑、编辑、艺术家等页面仍各自显示局部错误提示；已有全局禁网、离线和普通错误已统一移至侧栏设置正上方，不再占用主内容顶部。
- **目标与验收**：联系方式为空时所有出网入口在界面上同样禁用，并显示统一原因与设置跳转；网络错误不伪装无结果，重复错误在统一位置合并提示。

## G11 — 不确定署名的专门人工确认

- **现状**：初次创建、手工编辑及补全已同步署名成员；不确定标记独立保存，成功补全不再清除。仍没有针对署名拆分结果的专门人工确认界面；普通编辑可修改署名与角色，不能替代成员边界确认。
- **目标与验收**：展示待确认的署名边界、允许用户明确成员及顺序，确认后同步区间与索引；遵循艺术家规格中的双 CV 署名成员及受限演唱兜底，不把普通署名或单独配音关系当作歌曲演唱证据。

## G12 — 清单数量上限

- **现状**：iTunes 的 `lookupLimit` 固定为 200，没有按声明总数追加获取。
- **目标与验收**：超过 200 条时提供完整获取方案或明确的不可取全提示，并保留 partial 状态。测试不能仅用 120 首样例证明任意长度清单完整。

## G13 — 标签排序

- **现状**：`frontend/src/stores/library.ts` 对歌单和标签均传 collectionId；`internal/store/library.go` 对该条件统一按集合 position 排序，没有区分种类。
- **目标与验收**：歌单默认恢复保存位置，标签忽略集合位置并采用普通曲目排序；验证从表头排序回到默认顺序及重新打开页面。

## G14 — 封面来源真实网络复测

- **现状**：QQ 搜索已改用 `u.y.qq.com/cgi-bin/musicu.fcg`（`DoSearchForQQMusicDesktop`），163 改用 WEAPI 歌曲搜索并按专辑聚合，2026-09-24 均已真实验通；CAA、iTunes 已完成真实搜索、预览和采用。原生窗口、输入法、文件选择及编辑相关人工验收已由用户于 2026-10-16 确认完成；此次确认不扩展为四来源的最新在线复测或真实断网专项证据。图片传输不使用环境代理，需要代理才能访问 archive.org 的网络无法获得直连加速。
- **最新复测**：2026-10-17 网易云搜索、预览及采用通过（请求档位 250，实际 240×240、16545 字节）。iTunes 进一步诊断确认原「世界中の雨」查询召回 20 条无关结果，被相关性规则过滤为 `empty`，不是来源错误；另以「ツバサ / 4円 / side-C / jp」完成搜索、预览和采用（250×250、13904 字节）。CAA 的 MB 召回仍受 TLS 握手超时阻塞；QQ 因同轮旧歌词接口 -1901 已停止，未再请求封面。不能把两个来源成功记成四来源通过，详见 [verification.md](verification.md)。
- **依据**：`internal/provider/{caa,itunes,qqmusic,netease}/` 的封面能力实现、`internal/app/cover_live_test.go`；历史验收见归档变更 `revise-album-cover-workflow/acceptance.md`。
- **目标与验收**：用 `SONEXA_LIVE_COVERS=1 go test ./internal/app -run '^TestLiveCoverSources$' -count=1 -v` 定期复测四来源，可用 `SONEXA_COVER_SOURCE` 限定来源；不以离线 fixture 代替真实来源，原生人工确认与真实网络复测分别记录。

## G15 — 旧模型的用户迁移边界

- **现状**：当前开发版本采用 `upstream-snapshot-v1` 模型代际，只支持清空历史应用数据后的新库初始化。检测到旧模型明确拒绝打开，不自动删库，也不转换旧数据与旧采用文件。
- **验证边界**：空库、新模型事务迁移、文件引用回滚及目录切换已覆盖；这些证据不代表历史数据库可升级。若未来需要保留旧收藏升级，须另行规划数据与采用文件迁移，不恢复已删除的隐式转换。

## G16 — QQ 音乐上游

- **现状**：QQ 音乐使用非公开的 `musicu.fcg` 与歌词接口，契约可能不经通知改变。碟序规律（`index_cd` 从 0 开始、`index_album` 为全专辑序号）与字段语义来自少量样本，`recordNum` 未核实，因此不映射目录号。元数据、封面查询、手动歌词及回退已共用 `qq` 平台桶；合计 HTTP 记账、重试/回退与设置生效的离线测试已通过。元数据单碟、多碟、真实缺失歌词回退和有界速率网络入口已加入。2026-10-17 搜索及单碟/多碟详情实际通过（3 次请求，约 2 秒间隔，HTTP 200/业务码 0），但缺少实际触发歌词回退的样例；随后一次授权的有界查找（2 次搜索、4 个有效详情、6 次请求）也都返回内联歌词，未命中回退。随后有界速率测试的 30 档三种查询均成功，45 档第二次封面查询出现 HTTP 200/请求块 code=2001，已停止，未运行 60 档或重试；错误与速率的因果关系未验证。本轮进一步授权的查找改用「夜に駆ける」「爱你（青春离别版）」，2 次搜索、5 个有效详情、7 次请求均成功且带内联歌词，仍未触发回退；没有重跑速率入口。随后获授权扩大为 10 标题/40 次的单轮查找，仅第一个标题 `An Ending (Ascent)` 就真实触发回退：专辑 `001Frvoh4E456m` / 歌曲 `000W46Kt3BWQ0i` 的旧接口返回 61 字节，但不是可用歌词；第二个候选的旧接口返回 -1901，累计 6 次后停止，未继续其他标题或 QQ 入口。成功补取歌词的样例仍缺失，未复跑 45/60 档。非 QQ 歌词/封面的独立结果见 G14/G17 和 [verification.md](verification.md)，不能由部分成功关闭接口可用性风险。
- **依据**：`internal/provider/qqmusic/`、`internal/app/{cover_quota_test,qq_settings_test,qq_live_test}.go`；速率选择依据及非官方边界见[架构设计](design.md#上游能力与装配)。
- **目标与验收**：按 [README](../README.md#qq-元数据与有界速率验证) 显式开启有界样本，覆盖搜索、单碟、多碟详情及真实歌词回退，记录发送间隔、HTTP/业务错误与 Retry-After。回退需要实际缺少内联歌词的样例，不能篡改响应制造成功；遇限制停止，不继续提速。

## G17 — 独立歌词来源与回归边界

- **现状**：当前仅网易云、QQ、酷狗三个歌词来源，均为非公开接口；酷我歌词能力、端点、配额及内嵌翻译规则已移除，不再作为待验收来源。已实现每源 Top 3、跨源内容排序、来源完整 XLRC 交付、三列阅读及同版本展示批准。接口样本成功不承诺所有歌曲或任意时刻可用。
- **最新 QQ 补充证据**：后续 `e26c0d3f` 修复使用原查询“夕立 / CROW'SCLAW / アコースティック・エピソード / 287000 ms”，真实生产能力验证在 6 次授权上限内发送 5 次。无词 MID 经新接口空响应、legacy 三码一致 -1901 归为候选级 no_lyrics，不再阻断；曲名补充召回的 3L 记录取得原文、翻译、罗马音及逐字，XLRC 12888 字节、0 警告、往返一致，匹配 80 且仍需人工确认。第三项罗马音仍解析失败，未隐藏或扩大探测。不能把单样例通过视为所有 QQ 格式失败已消除，见[后续验证](changes/archive/2026-10-31-improve-lyrics-normalization-and-ranking/change_record/e26c0d3f-tasks.md)。
- **先前 Top 3 证据**：2026-10-21“君の知らない物語 / supercell”授权轮次 18/40 次发送：网易云 3/3 普通 LRC 和附加通道成功但无有效 YRC，QQ 普通原文/翻译有效但 QRC/罗马音失败，酷狗 3/3 KRC 有效且语言部分提供，当时酷我无词导致整体 FAIL。这是后续修复前证据，不代表现行三来源已经完整重测，见[历史验证](changes/archive/2026-10-31-improve-lyrics-normalization-and-ranking/validation.md)；更早证据保留于 [verification.md](verification.md)。
- **格式与推断限制**：本地支持 UTF-8 TXT/LRC/XLRC，不转码 GBK/UTF-16，不导入二进制 QRC/KRC 或原始 YRC。在线 QRC/YRC/KRC 均规范化为 XLRC；YRC 配套字段修复及三来源在线 ±2 秒关联/语言补全有合成与历史响应离线重放，尚无全面最新在线验收。时间近邻和有限文字判别可能误配/误判，未知翻译默认 zh 是策略；声部/ruby 只保留明确标签。Sonexa 保真扩展不保证第三方 XLRC 工具无损互通，没有播放器/同步高亮或独立歌词导出 UI。
- **回归限制**：后续 Go/race、前端单测/构建及 Chromium/WebKit 歌词回归记录在归档 change_record；浏览器使用 Wails 替身，不能替代原生窗口、输入法或 TXT/LRC/XLRC 文件选择器人工验收。早期全量 Playwright 241/242 的编辑器徽标基线失败也不能由歌词定向通过推定已修复。
- **归档保留的未完成项**：用户于 2026-10-31 确认带警告同步归档，原 tasks 9.3 完整真实来源验收、9.4 Wails 原生窗口人工验收保持未勾选，不把归档当作完成证据。酷我部分因能力移除不再要求补测，其余网络及原生缺口继续在本条跟踪。
- **目标与验收**：另经显式授权按 `SONEXA_LYRICS_LIVE=1 go test ./internal/app -run '^TestLiveSources$' -count=1 -v` 有界复测当前三来源，用 `SONEXA_LYRICS_SOURCE/TITLE/ARTIST/ALBUM/DURATION_MS` 限定样例，记录缺失、错误和部分成功，遇限制停止；重点补 YRC 配套轴及现行 XLRC 全链路，另在原生窗口核对预取、徽标、排序、三列/原始切换、明确采用、回读和文件选择器。不以离线/历史响应或文档校验替代新网络/原生证据。
