# Sonexa 架构设计

行为规格见 [功能索引](README.md)，实现限制见 [已知问题](known-gaps.md)。

## 技术栈与模块

Wails v2 + Go；Vue 3 + TypeScript + Tailwind CSS v4 + Volt + Lucide Icons + Pinia。

| 目录 | 职责 |
| --- | --- |
| `main.go`、`internal/app/desktop.go` | 嵌入前端资源、启动 Wails、配置生命周期和本地封面服务 |
| `internal/app/` | 前端绑定、业务协调、导入与详情补全调度 |
| `internal/domain/`、`internal/library/` | 三层快照与字段状态；归组、准入、编辑预览及保存计划 |
| `internal/store/` | SQLite、模型代际、当前值/快照、事务引用、查询和全文索引 |
| `internal/provider/` | 元数据契约与注册表、通用 HTTP 缓存、限流、重试、图片策略和出网检查；各具体上游子包实现所支持的能力 |
| `internal/matching/` | 文本处理、候选评分、本地重复检查与自动入库判定 |
| `internal/importer/`、`internal/export/` | 表格解析、持久化队列、CSV / JSON 导出 |
| `internal/covers/`、`internal/config/` | 通用封面目录、用途解析、下载工作池、专辑图片文件与本地图片服务；数据路径与设置 |
| `internal/covers/sources/` | 封面搜索消费侧契约、来源集合、相关性规则；不含具体来源协议 |
| `internal/lyrics/` | 歌词消费侧契约、来源集合、候选评分、通道状态与合并文本；不含具体来源协议或元数据注册 |
| `frontend/src/` | 页面、共享组件、状态管理与统一 API 入口 |

Volt 组件源码位于 `frontend/src/volt/`，基于 `primevue@4.5.5` 的无样式模式，使用本地 Tailwind 样式与 Lucide 图标。颜色统一定义在 `frontend/src/style.css` 的 `--p-*` 变量中。来源与许可见 [组件说明](../frontend/src/volt/README.md)，依赖版本以锁文件为准。

## 上游能力与装配

`provider.Upstream` 只提供稳定 ID 与显示名。`provider.MetadataProvider` 保留元数据字段能力、
速率声明、配置检查、搜索、Refs、候选快照、补全与发行摘要/详情；`Registry` 仍只登记元数据。
`VersionLister`、`ArtworkStrategist` 是可选契约，字段能力位不等于封面/歌词服务能力。
已删除旧大接口及其强制 `SearchCovers`，不保留永久兼容层。

| 上游子包 | 元数据 | 封面搜索 | 独立歌词 | 自动图片 |
| --- | --- | --- | --- | --- |
| `musicbrainz` | 是 | 为 CAA 提供窄发行召回 | 否 | 薄委托 CAA |
| `caa` | 否 | 是，共享目录服务读取 | 否 | CAA 目录、图片及 archive.org 降级 |
| `itunes` | 是 | 是，保留地区 | 否 | 原发行图片策略 |
| `qqmusic` | 是 | 是 | 是 | 按专辑 MID 构造 |
| `netease` | 否 | 是 | 是 | 不增加自动取图 |
| `kugou`、`kuwo` | 否 | 否 | 是 | 否 |

```text
app/upstreams.go → 各 provider/<upstream> 实现
       ├─ provider.Registry（MetadataProvider）
       ├─ lyrics.Service / Registry（lyrics.Provider）
       └─ covers/sources.Registry（sources.Provider）
provider/<upstream> → 消费侧契约、provider 父包、domain
lyrics、covers/sources → provider 父包、domain / matching
covers → provider 图片策略、domain / store
provider 父包 → domain（不反向依赖业务或具体上游）
```

歌词与封面集合类型明确，构造时拒绝重复 ID，列表、来源校验及执行读取同一份登记；
元数据 Registry 保留原覆盖语义。默认顺序分别为 163/QQ/酷狗/酷我、CAA/iTunes/QQ/163，
元数据按设置排序，导入仅 MB。公共 Wails 绑定及 DTO JSON 结构不变。
封面结果只能是新 `CoverCatalogInput` 或已登记的 `CoverCatalogKey`，后者只读取，
不会二次保存覆盖 CAA 实际发行、目录版本或文件关联。

QQ 三用途复用私有歌曲搜索原语，元数据和手动歌词共享 musicu envelope/请求块状态解析，
但分别保留整次失败与通道部分成功策略；网易云两用途复用 WEAPI 及搜索响应解析。
各能力独立投影关键词、召回数量和结果身份，不强迫封面/歌词经过元数据过滤。
CAA 目录与缩略图共享索引解码及结构校验，目录身份/档位校验不混入缩略图回退。
QQ 旧歌词端点也只有一份传输与解析：元数据优先详情原文、缺失才回退，手动歌词另有通道与逐字策略。
QRC/DES/zlib/XML 位于 `provider/qqmusic/{qrc.go,qrcdes/}`，MIT 许可证及来源提交随代码保留。
通用文本校验、评分、通道合并留在 lyrics；获取总超时覆盖配额等待、重试和所有子请求。
网易云占位文案在 `provider/netease/lyrics.go` 归一化为无歌词或通道 unavailable；
lyrics 不使用跨来源正文黑名单，只处理 UTF-8、大小、文本格式与通道合并。
来源占位不得掩盖超限或损坏，其他来源的同文案真实正文不因此被拒绝。

`assembleUpstreams` 不写盘、不出网、不重配桶，先验证三个业务集合及图片策略；
`publishUpstreamsLocked` 在 App 锁下发布并原位配置长期 Limiters，启动先建封面服务，
CAA 不捕获空目录依赖。设置更新先构建，失败不发布半套能力；目录移动继续走
`MoveRoot`，服务和工作池不替换。新会话使用新集合，旧会话保留服务/策略快照；
动态门禁仍读取当前设置，共享桶的排队权不会因新实例重置。关闭先阻止新工作、取消会话与自动图片，
等待封面/歌词绑定及封面池退出，再关闭文件服务和 Store。

图片许可由可信后端适配器声明、按实际图片来源注入，不能从前端或响应扩充；
首次请求、自动降级、每次重定向都使用所属来源策略，不合并其他来源许可。
公共传输保留 HTTPS、TLS 验证、主机点边界、默认/443 端口、无用户信息、有限跳转与动态门禁。
本地保存图片命中不要求出网许可。`ArtworkStrategy.CatalogKeys` 统一提供有效、有序的主目录及后备目录身份，
自动解析、未入库候选的本地预览读取和入库复用都使用同一声明，不再使用 `GroupFallback`。
`covers.Resolve` 只有当前目录为 empty 才推进；错误或取消停止远程目录回退，found 目录的规格尝试不跨目录身份，
仍保留本地可用图片兜底。CAA 声明有效 release → 已绑定有效 release-group，iTunes/QQ 只声明自身有效专辑目录；
后备目录已存预览可直接离线读取，不为复用再走网络。仅有手动封面能力不自动启用取图，
共享池并发、图片安全策略、动态门禁、会话快照和采用文件保护保持不变。
已删除无调用的 iTunes `ResolveArtwork` / `VerifyArtwork` 和 `Client.Head` 直连探测链；
仍在候选预取与自动降级中使用的 `ArtworkLadder`、CAA URL 工具和 `LegacyLadder` 策略保留，
图片可用性由封面池下载、解码及降级确认，不另走 API 客户端探测。

API 使用 `provider.Client`，缓存模式明确区分 `UseCache`、`RefreshCache` 与 `NoStore`。
元数据刷新跳过读但写回，独立歌词及 QQ/163 手动封面查询不读写原始响应缓存；
CAA/iTunes 手动召回沿用元数据刷新，目录单独持久化。生产请求使用平台配额键
`qq`、`163`、`kugou`、`kuwo`，MB/iTunes 封面召回复用其 API 桶；CAA 索引和全部图片只走封面池。
合计 HTTP 到达记账、重试/回退、新实例、其他平台隔离和图片例外已由
`internal/app/cover_quota_test.go` 验证；启动规范化、非法保存无副作用与排队变速见
`internal/config/qq_rate_test.go`、`internal/app/qq_settings_test.go` 和 `internal/provider/quota_test.go`。
QQ 的规范性速率设置规则集中在[主上游设置规格](specs/platform/settings/spec.md#requirement-qq-合计请求速率设置)，在线可用性及有界速率的未完成验收仍见 G16 与核对记录。

默认选择的工程依据：旧实现的元数据/歌词桶为每分钟 30 次，另有每秒一次的封面桶，
同时繁忙时理论合计约每分钟 90 次；新的合计默认是 45，既提高原元数据/歌词桶速率，
也收紧了旧双桶总量。历史约 1.2 秒的串行请求说明及封面每秒一次仅是保守工程参考，
不是本轮测得的安全额度或官方承诺。真实来源入口、少量速率样本和请求上限见
[开发说明](../README.md#qq-元数据与有界速率验证)；离线通过不证明在线可用或长期安全。

## 数据模型

`release_group → release → track` 分别管理本地组、具体发行和收藏；曲目可无发行。每层身份、`*_current` 与 `*_snapshot` 分开，字段状态区分 unknown、empty、value，当前值记录 follow/user。名称和署名均可空，不写入“未知专辑”等展示占位。

- 年份、位置、风格、演唱/作曲/作词及歌词归曲目；专辑标题、艺术家、类型、碟数/每碟曲数与采用封面归具体发行。其他参与角色、厂牌、国家、标识等为只读事实。
- `release_group_ref` 保存组的多来源身份；完整的名称/署名与原生身份独立提供归组证据。多组冲突由用户确认合组，后台补全只保存独立提议。
- `release_snapshot_track` 保存上游清单，收藏按精确来源/发行/曲目身份判断；同录音的不同收藏不合并。各发行保留全部收藏，展示代表不决定收藏清单；`albumRows` 可按可靠证据合并展示行，但保留全部本地 ID 与灰色行的真实发行上下文。最后一首收藏迁出或删除后，同事务清理空发行、附属记录和名称证据，更新组修订及代表引用，空组与映射一并清理。
- 当前署名成员、角色、标识投影和 FTS 在写事务中同步。完整 CV 身份与独立声优均作署名成员，整体不借用部件身份；`credit_cv` 仅在没有明确演唱集合时提供可靠 CV 当前投影，明确角色与用户清空优先，不伪造上游快照。详情读模型将派生演唱映射为完整 CV 名称和链接，不改存储角色；无可显示角色时只显示空态，不在参与者区域以普通署名兜底，存储署名与关联仍保留。
- 歌词采用 UTF-8 不可变文件，独立搜索的原文、翻译、罗马音与逐字状态只在内存会话 DTO 中保存，采用对象是最终合并文本，不新增数据库通道字段；封面继续使用来源目录、图片、规格、文件与采用引用。临时草稿和正式引用分开，数据库失败可回收本次无引用产物，旧文件保持可读。

SQLite 开启 WAL 与外键，先检查 `upstream-snapshot-v1` 模型代际，再执行新模型编号事务迁移。旧模型明确拒绝打开，不自动清理或转换；不将移除旧转换视为历史升级验收。新模型中版本过高同样拒绝打开。

## 主要流程

1. 元数据注册表提供候选转换、精确补全、摘要、身份解析及可选版本/自动图片能力；歌词和手动封面搜索由各自集合分发。三元数据来源输出同一快照语义；导入只使用 MusicBrainz，交互入口使用设置排序的注册表来源。
2. 自动选版先限定同组和可靠的同曲目候选，优先库内已有发行，再比较发行总数、非世界国家和稳定身份；展示载体/国家偏好不参与选版。未知总数或对应歧义进入复核。
3. 所有创建发行和成员变化经 library 准入计划；已有组新增成员需要独立批准。服务端计划有 15 分钟有效期、内容签名和幂等结果；提交在 SQLite 写事务内重查身份、证据和成员。
4. 精确补全按请求前修订和身份同步，只更新跟随字段，unknown 不降级事实，用户角色按角色保护；不拥有迁组或换绑权限。
5. 编辑器分开离线基线、上游预览与草稿。左侧“使用”自动准备完整且有效的精确预览，冻结确认后一次填入已知值；内部身份仅用来源和语义状态表达。未切换发行上游可原地修改共享信息，保留发行与收藏关系；新建本地专辑或关联新上游时才进入逐曲影响页，原地修改不可换上游。新建仅迁入明确勾选歌曲，目标已存在则复用并保护其用户值。两种保存方式均检查位置与相关修订，取消保留草稿。
6. 保存固定字段、绑定、保存方式、迁入集合、对应位置及文件动作，事务内重验相关修订与准入；原地修改封存全部关联歌曲修订，结构变化检查全部收藏位置，仅当前编辑歌曲接收歌曲字段草稿。新发行提前选择 JavaScript 安全整数 ID 而不创建实体，用于提交前准备最终封面目录；事务检验碰撞。失败保留旧正式数据与草稿，成功发布统一刷新事件。
7. 封面来源策略保留缓存、配额、共享工作池和取消语义；编辑采用先暂存，不调用立即采用接口。明确使用上游封面时读取上游预览，不把目标的用户采用误当上游值；既有详情页独立采用入口仍可使用。
8. 独立歌词搜索按来源建立有界内存会话，关闭取消、30 分钟失效，不读写原始响应缓存。候选复用默认评分，局部准入与高置信规则不影响元数据；汇总当前来源后才自动预览高置信最优项，人工选择优先，采用仍须明确点击。`StageLyrics / SaveLyrics` 复用文件哈希、事务引用及曲目修订，只改当前歌词，保留既有 user/follow 比较规则。
9. 歌词能力执行复用 provider 传输、当前门禁、交互优先级、共享平台桶与有限重试；上游专有编码、错误与回退由适配器处理，业务仅接收候选或 Payload 并组装 Document。手动 QQ 批量请求逐字与普通块，保留可用通道，必要时回退；元数据不改用手动逐字链路。协议及内容边界见[歌词搜索](specs/upstream/lyrics-search/spec.md)和[QQ 音乐](specs/upstream/qqmusic/spec.md)。

## 前端约定

- `TrackTable`、`CandidateTable` 分别统一曲目和候选列表。`useListSelection` 管理选择、焦点与锚点，`trackRows` 管理排序和稳定行标识，避免组件内部再次排序或选择。
- 普通列表与专辑列表分别保存列偏好；专辑固定位置顺序，记住合并/拆分 group 模式，各分区及合并视图独立展开清单。浏览条件取交集，名单查找与曲目搜索分别处理。
- 详情、设置、导入、编辑使用应用内组件。模态限制尺寸并内部滚动，`dialogStack` 控制 Escape 只关闭顶层。
- `useEditDraft` 管理草稿与请求归属；准入和归组提议使用具体展示 DTO，完整快照及计划签名留在服务端，避免 Wails 泛型数组构造问题。
- 前端通过 `frontend/src/api/` 调用 `frontend/wailsjs/go/app/`；模型命名空间为 `Models.app`。时间跨绑定传递为 RFC3339 字符串。
- `App.emitEvent` 统一发送事件，测试可替换事件发送函数。导入成功提交及逐首补全成功立即发送 `library:changed`，失败/取消不伪报；最终导入进度在运行标记清理后发送。`refreshQueue` 合并连续事件为串行续读，请求序号隔离旧响应，刷新保留当前导航、草稿与内容。详情、艺术家、专辑、库内搜索和上游候选本地徽章随库变化更新；候选重判只查本地，不自动重搜上游。
- 当前批次进度与全批次待选+失败汇总分开，侧栏不以单批 review 冒充总数；复核页响应状态与候选变化，不依赖计数改变。补全工作器只累计当前 pending 集合，暂停/重试保留进度，下一批或重启重新计数，仅全部曲目页且仍有 pending 时显示入口。
- 封面采用后发送带发行与 revision 的封面变更事件，列表、详情、专辑和候选按目标与版本刷新；全局禁网、离线和普通错误统一放在侧栏设置上方，局部错误的剩余限制另列 known gaps。
- 封面与歌词搜索大弹窗由 `App.vue` 挂载，会话状态分别在 `stores/coverSearch.ts`、`stores/lyricsSearch.ts`；打开时背景设为 inert，关闭、目标或浏览视图变化即取消会话。详情抽屉通过 `useDrawerWidth` 保存调宽偏好，详情与歌词双页切换；详情歌词隐藏标签，搜索预览保留最终合并文本和时间标签。
- 两个搜索 store 每次打开共同等待登记列表和目标修订，确认当前打开代次后才 ready；页面直接使用 store 列表。`lib/sourceSelection.ts` 负责首次全选、重开保留选择交集及去重、单来源重试校验；空列表、加载失败或迟到响应不恢复固定名单或旧状态。封面地区控件读取已选来源的 `needsCountry`，不判断 iTunes ID，统一传递显式地区并由适配器处理空值默认规则。行为契约集中在[搜索来源选择生命周期](specs/upstream/provider-registry/spec.md#requirement-搜索来源选择生命周期)。

## 构建与测试

Wails 绑定、`dist/`、测试报告为生成产物，不提交。首次检出或修改 Go API 后先生成绑定，命令见[开发说明](../README.md#开发与验证)。

Go 测试通常与实现同包，跨上游组合测试放在 `internal/app`，避免反向导入造成循环；生产依赖由 `internal/acceptance/upstream_boundaries_test.go` 检查。离线测试数据位于 `testdata/`。业务回归应经过实际绑定、解析和隔离数据库；仅测试存储函数不足以证明页面功能完成。前端使用 Vitest 及带 Wails 测试替身的 Chromium/WebKit 回归。2026-10-16 用户确认的原生人工验收属于此前上游/编辑器变更，不扩展为后续独立歌词功能验收；最近文档同步、既有浏览器失败及历史测试边界见[核对记录](verification.md)，后续原生回归及大曲库性能仍须使用独立证据。
