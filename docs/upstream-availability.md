> 实测日期：**2026-09-24**。只讨论上游能力、获取方式和实际可用性，为后续开发提供依据；不包含现有项目支持情况。

每份报告包含普通信息、丰富信息、其他信息的字段矩阵，端点 / 请求参数，实际样本，限制与资料链接。[结构化测试记录](upstream-test-evidence.json)收录 63 条主要请求记录，以及 HTTP 入口诊断、加密校验、离线解析说明；保存请求参数、HTTP / 业务结果、耗时和原始响应摘要哈希，不含完整歌词或封面内容。

## 总体判断

| 来源 | 本次在线元数据可用性 | 适合获取 | 关键不足 |
| --- | --- | --- | --- |
| MusicBrainz | 搜索、详情、关系查询成功；CAA 图像成功 | 发行身份、词曲 / 演唱关系、轨碟、类型、国家、目录号、条码、ISRC | 社区覆盖不完整；无歌词正文；限流严格 |
| iTunes | 搜索、lookup、UPC 输入查询、图片成功 | 基础署名、专辑、轨碟、日期、主风格、封面 | 无完整人员、歌词、词曲 / ISRC 标准输出；Album 不能区分 EP / 单曲 |
| 网易云 | 标准 WEAPI 的搜索、详情、专辑、歌词、百科块成功；UGC 端点业务失败 | 中文 / 日文基础信息、封面、LRC / 翻译 / 部分逐字歌词、专辑类型 | 词曲多来自歌词文本；未署名主唱可能缺失；无可靠标准发行标识反查 |
| QQ | 新 POST 搜索、丰富详情、专辑、歌词 JSON / JSONP 成功；旧搜索 HTTP 500 | 基础信息、结构化角色条目、歌词、封面、专辑类型 | 方法差异明显；人员不完整；多碟序号需校验；ISRC / UPC 未取到 |
| VGMdb | 主站 HTTP 403；第三方 vgmdb.info TLS 失败 | 内容模型适合 VGM / 动画发行目录号、条码、曲目、credits、扫描图 | **实时元数据未验证可用**；只有历史样本离线解析与单张 CDN 图片成功 |

不存在“一个来源能完整、可靠地取得所有要求字段”的证据。尤其是 **所有演唱者**，不能因返回了一组艺人就标记为完整。

## 必须统一的字段语义

- **署名 ≠ 演唱**：制作组合、作曲家、虚拟角色、声优和伴唱都可能出现在不同层级。MusicBrainz 实测能在 supercell 署名之外取得 nagi；QQ / 网易云的同名作品样本没有取得。
- **专辑级 credits ≠ 曲目级 credits**：VGMdb 的整张原声参与者不得直接复制到每一轨。
- **日期有层级**：歌曲首次发行、选中专辑发行、发行组首次发行、版权年份、商店上架和现场演出年份不能共用一个无语义字段。
- **轨号必须属于具体发行**：QQ 多碟实测 index_album 是全专辑序号，且返回数组乱序；不能按数组下标写碟内音轨号。
- **国家 ≠ 语言 ≠ 商店地区**：iTunes country 是店区；网易云 / QQ 的日语、国语不是发行国家。
- **厂牌名 ≠ 目录号 ≠ 条码**：company、catalog number、UPC / EAN / JAN、ISRC、平台 ID 应分开；QQ recordNum 本次有值但标准语义仍待核验。
- **类型 ≠ 风格**：iTunes collectionType=Album 不代表标准“专辑”；VGMdb Arrangement / Commercial / CD 分别是不同维度，不是 genre 或 Album / EP / Single。
- **HTTP 成功 ≠ 业务成功 ≠ 有数据 ≠ 匹配正确**：网易云 HTTP 200 / code 301、搜索只有翻唱、目录有图但图片失败，均需独立表示。

## 实测方法与边界

- 运行环境：macOS，curl 8.7.1 / LibreSSL 3.3.6、Python 3；图片实际尺寸用系统解码工具核对，不以 URL 中的数字代替。
- 网络：本机直接请求，没有配置显式 HTTP(S) / SOCKS 代理。**未确认出口国家 / 地区**，不把结果推广成“中国大陆直连”或“全球可用”。
- 无账号登录、无 Cookie 注入、无私有 token；没有读取本机浏览器凭据，没有规避验证码 / Cloudflare 挑战或版权限制。
- 请求采用 `User-Agent: SonexaMetadataResearch/0.1 (+https://github.com/norhua/sonexa)`；QQ / 网易云另带各自主站 Referer。
- MusicBrainz / WEAPI / musicu 请求保守串行，MusicBrainz 间隔至少 1.2 秒；iTunes API 连续请求间隔至少约 3.1 秒。不同上游可独立测试；这些安排不代表对未公开服务配额的承诺。
- 测试覆盖日文 Vocaloid、未署名主唱案例、中文流行曲、多碟现场专辑、单曲 / EP 形态和 VGM 历史发行。**不是曲库覆盖率统计、持续可用率、压力测试或 SLA 验收**。
- 不下载歌曲音频。歌词只做字段、编码和格式检查；报告不复制完整歌词。VGMdb 历史样本只用于离线验证，明确与实时数据分开。
- 原始请求记录、响应、图片及临时验证脚本留在本地 `tmp/upstream-research/`；该目录不提交。报告与结构化测试记录可以独立阅读，重新测试按各报告示例执行。

## 后续开发的选择建议

1. 以 MusicBrainz 处理发行 / 录音 / 作品身份和高语义精度关系；允许真实缺失，不自动推断所有人员。
2. 用 iTunes 快速补普通信息、商店清单和封面，但不要期待它提供免费完整 credits 或歌词。
3. 用 QQ 丰富详情补充词曲、人员角色和歌词；网易云作为基础字段及歌词的另一来源。两者都需要可降级、按端点验证的适配层。
4. VGMdb 先解决合规、可持续的访问渠道；目前不宜成为必须成功的在线依赖。
5. 对每个字段保存来源、实体层级、提取方式（结构化 / 歌词头部 / notes / 推断）、时间、原值；发生冲突时保留候选，不用后来的空字段覆盖已知数据。

以上是工程建议，不构成内容许可结论。数据可获取与可存储、可展示、可再分发是不同问题，特别是歌词与封面。
