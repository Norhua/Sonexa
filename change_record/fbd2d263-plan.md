## 完成记录

### 详情抽屉

- 根因：`App.vue` 单独持有详情快照；编辑器 `saved` 与 `library:changed` 都只刷新列表/计数，没有重读详情。
- 修复：保存成功及曲库变更时刷新当前打开的详情，包括歌曲、角色、发行、歌词和标签；共享专辑修改也刷新当前展示的另一首关联歌曲。不在草稿阶段修改详情。
- 请求归属：单独记录当前请求目标，避免已请求 B、仍显示 A 时后台刷新重新请求 A；较旧响应、关闭后的响应和卸载后的响应不生效。封面更新复用同一刷新入口。
- 修改位置：`frontend/src/App.vue`。新增回归：`frontend/tests/e2e/detail-reactivity.spec.ts`。

### 复核队列

- 根因：页面只在挂载和处理动作成功后读取队列，未消费 `import:progress`；原来的 `watch(current)` 又会在替换同条目对象时清空搜索交互状态。
- 修复：页面存活期间直接订阅导入事件，不依赖计数变化、不轮询；连续事件合并为串行读取并保留一次续读。空队列新增、失败变化和候选变化均及时呈现，并刷新任务汇总。
- 列表协调：按条目 ID 保留当前条目，只有目标消失才选择相邻条目；同 ID 刷新保留输入、上游/地区、候选展开状态及“已经手动搜过”的状态。
- 异步边界：搜索结果写到最新的同 ID 对象；队列旧快照不覆盖进行中/刚完成的搜索；成功处理动作使此前队列及搜索响应失效；切换条目或离开页面不接受旧结果，并取消订阅。
- 错误处理：刷新失败保留已展示内容和草稿，后续事件成功清除刷新错误；后台刷新不清掉用户处理动作/搜索错误，准入取消保持原有语义。
- 修改位置：`frontend/src/views/ReviewView.vue`。扩展回归：`frontend/tests/e2e/review-actions.spec.ts`。

## 其他响应式更新遗漏（仅排查，未修复）

以下不是本轮新增的产品决策。前四项及第五项的导入前端链路使用临时 Chromium + Wails 桩件探针核对，不写入业务代码，不操作真实应用数据；补全及上游徽章部分为代码链路确认，尚未做原生验收。

1. **艺术家名单、曲目计数与角色分面**：`frontend/src/views/ArtistsView.vue` 的名单只监听标签，分面只监听导航上下文，没有监听 `library:changed`。编辑署名/角色、删除收藏后，右侧曲目可能已更新而中列及分面仍旧。探针中发出曲库事件后 `ListArtists` 与 `GetArtistHeader` 调用数均仍为 1，界面保留旧名称和旧计数。对应编辑规格「成功后统一刷新……艺术家」的既有遗漏。
2. **搜索结果与本地命中状态**：`frontend/src/stores/search.ts` 保存独立的 `libraryRows`/`upstreamRows`，`SearchView.vue` 不监听曲库变更。资料库搜索结果在编辑、删除或标签变化后仍旧；探针确认后端已返回空库且曲库列表重新读取，搜索仍展示被删除的歌曲。上游结果只在当前行“加入”成功后就地打本地徽章，其他入口入库/删除/改绑定以及同次结果中的关联行不会重新判定，可能保留过时的“已在库中”。后者为代码确认。
3. **导入队列状态切换**：`frontend/src/views/ImportQueueView.vue` 只监听 `tasks.summary?.processed`。处理数不变的 done/paused、失败重排、批次切换等事件不会必然触发读取；`load`/`refresh` 还缺少旧响应保护。探针在页面已显示 10/10 进行中时推送 done=true、processed=10，`GetImportQueue` 仍只调用一次，页面继续显示进行中。
4. **侧栏待复核总数**：`frontend/src/stores/tasks.ts` 将进度事件的 `p.stats.review` 直接用作全局 `reviewPending`，遗漏失败条目和其他批次；而 `GetTaskSummary` 返回全部批次待选+失败总数。探针中的 review=1、failed=2 事件使侧栏显示 1。停留复核页时本轮新增的汇总读取会纠正它，但其他页面仍存在少计/回跳，任务汇总请求也没有防止旧响应覆盖新进度的序号保护。
5. **后台导入/逐首补全后的库内容**：`internal/importer/runner.go` 直接调用 library service 入库，仅推送导入进度；`internal/app/app.go:emitProgress` 不发送曲库变更事件，普通曲目列表与专辑页又不订阅导入事件。探针确认停留全部曲目时推送导入进度不会调用 `ListTracks`。补全工作器 `internal/app/enrich_worker.go` 每首只推送进度，到整轮退出才调用 `onRunFinished` 发送曲库通知，因此长任务中已补好的字段/角色通常要等一轮结束或其他刷新才显示。当前抽屉已能消费曲库通知，但本轮没有扩大到修改这些后台通知时机。
