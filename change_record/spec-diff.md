# 实现与 Spec 差异记录

本文件由测试修改阶段的各次会话共同维护；本阶段不直接修改 `openspec` 文档。这里只记录已确认的产品调整及其实现差异，不将本次页面调整扩大为对整个项目的规格审计。

## 305ddf59：编辑页面重写（已实现，2026-10-03）

### ED-001：“使用”按钮移至左侧上游控制栏

- 关联规格：`openspec/specs/editing/track-editing/spec.md` 及 `openspec/changes/unify-upstream-and-redesign-track-editor/specs/editing/track-editing/spec.md` 的「字段比较与草稿」「确认使用当前上游」；变更设计文档 §5「两栏编辑会话与『使用』」。
- 现行描述：右侧顶部展示绑定与“使用”按钮。
- 本次决定：来源下拉、搜索与“使用”集中在左侧顶部，明确“使用”面向左侧选定的预览。
- 保持一致：使用仍需确认，填入全部可用字段与身份草稿，未知值不清空；底部仅保存/取消，不提供“全部应用”。
- 实现位置：`frontend/src/views/EditDialog.vue`。

### ED-002：绑定与只读事实不展示内部身份

- 关联规格：上述两份编辑规格的「字段比较与草稿」「新建专辑影响确认与曲目对应」，以及变更设计文档的绑定与只读身份展示。
- 现行描述：规格要求可修改绑定、行业标识等只读，并在影响确认中展示前后身份；设计布局还列出歌曲身份、具体发行和本地组。规格没有要求 UUID 必须常驻主页面。
- 本次决定：编辑页以来源名称、绑定状态、歌曲及专辑标题表达身份；迁入确认以“绑定保持不变／解除歌曲绑定／重新关联某来源歌曲”说明身份变化。不直接呈现上游 UUID、录音/作品 ref、内部组 ID；手动修改弹窗按需接受链接/标识，打开时不预填已有标识。
- 边界：这是信息呈现调整；底层身份、唯一性校验、精确匹配和保存计划保持原有机制。ISRC、ISWC、条码等有业务含义的行业标识仍可在只读信息中查看。
- 差异性质：细化“可修改绑定”的入口，收敛设计中的身份展示；影响确认不再直接列出前后原始身份，后续同步文档时需采用上述语义描述。
- 实现位置：`frontend/src/views/EditDialog.vue`、`frontend/src/lib/editorDisplay.ts`。

### 不构成差异的设计整理

- 曲名/艺术家/专辑搜索同排、两栏滚动、字段对照和歌词弹窗属于布局细化，现行规格未禁止。
- 当前绑定的“重新获取”只更新快照草稿及上游列，保留手工值和左侧候选预览；封面查看只进入临时预览，采用仍需草稿操作和最终保存。
- `tmp/claude-plan/02-edit-page-design.md` 中旧版“全部应用”与“使用只设置绑定”的描述已被用户明确覆盖，不据此恢复旧行为。
